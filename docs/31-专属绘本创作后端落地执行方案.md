# 专属绘本创作后端落地执行方案

> 依据：`29-专属绘本创作统一实施说明.md`、`30-专属绘本创作UI执行方案.md`。  
> 目标：把“专属绘本创作”后端落地顺序、接口契约、数据边界和验收标准固定下来，避免实现时发散。  
> 当前判断：后端已经有直接创作主干，本阶段不重做主干，优先补齐照片素材、资产引用、视觉参考和生成门禁。

## 1. 当前后端基线

### 1.1 已存在能力

当前代码中已经存在专属绘本直接创作的主干：

| 层级 | 文件 | 已覆盖能力 |
| --- | --- | --- |
| Controller | `server/src/controllers/storybook_creation.rs` | 创建会话、恢复最新会话、更新想法、刷新理解、素材 patch、生成方向、选择方向、生成大纲、更新大纲、视觉偏好、开始生成、放弃会话。 |
| Application | `server/src/application/storybook_creation.rs` | 权限校验、会话状态流转、方向/大纲生成、幂等生成、生成任务入队。 |
| Repository | `server/src/repositories/storybook_creation_sessions.rs` | `storybook_creation_sessions` 的创建、查询、更新、锁定读取、生成任务写入、故事壳创建和内容替换。 |
| Migration | `server/migration/src/m20260814_000021_create_storybook_creation_sessions.rs` | 会话表、状态索引、storybook/job 外键、幂等索引。 |
| Models | `server/src/models.rs` | `StorybookCreationSession`、`CreationMaterial`、`StoryDirection`、`CreationOutline`、`VisualPreferences`、生成响应。 |

### 1.2 本阶段不要重做的部分

- 不重写 `storybook_creation_sessions` 主流程。
- 不拆掉现有 `directions:generate`、`outline:generate`、`storybook:generate`。
- 不把前端照片状态继续留在本地 mock。
- 不先做批量定制、review 证据、来源书变化计划，这些放到后续阶段。

### 1.3 当前最大缺口

前端已经形成“上传照片 -> 标注用途和名字 -> 生成同画风视觉参考 -> 用户确认 -> 进入故事计划”的体验，但后端还缺稳定业务真相：

- 原始上传文件。
- 本次创作里的照片引用。
- 用户填写的照片名称和用途。
- 视觉参考生成任务。
- 视觉参考确认状态。
- 生成前门禁。
- 刷新页面后的恢复数据。

因此后端第一优先级是：**照片资产引用与视觉参考闭环**。

## 2. 后端落地原则

1. `session` 是创作草稿真相；照片不能只存在前端 state。
2. `asset` 只代表上传文件；业务流程使用 `asset_reference`。
3. 选择“使用”的照片，必须完成同画风视觉参考确认后，才能进入绘本生成。
4. 删除照片是逻辑撤销本次创作引用，不要求物理删除原始文件。
5. 所有会影响生成输入的操作都要让方向和大纲失效。
6. 生成任务输入必须冻结当时的素材、引用、视觉参考和大纲快照。
7. 同一用户重复点击上传完成、确认参考、开始生成时，要可幂等或可安全重试。

## 3. Phase 1：照片资产引用与视觉参考闭环

### 3.1 建议新增领域对象

#### `storybook_assets`

表示用户上传的原始文件。

| 字段 | 说明 |
| --- | --- |
| `id` | asset id。 |
| `workspace_id` | 空间。 |
| `uploaded_by` | 上传用户。 |
| `storage_key` | 存储路径或对象 key。 |
| `original_filename` | 原文件名。 |
| `content_type` | MIME。 |
| `byte_size` | 文件大小。 |
| `width` / `height` | 图片尺寸，可异步补充。 |
| `status` | `uploading` / `uploaded` / `processing` / `ready` / `failed` / `deleted`。 |
| `processing_message` | 面向前端的处理状态说明，可为空。 |
| `visibility_scope` | 默认 `creation_session`，Phase 1 不允许自动进入公共或空间素材库。 |
| `retention_policy` | 默认 `session_scoped`，用于后续清理任务判断。 |
| `deleted_at` | 逻辑删除时间，可为空。 |
| `created_at` / `updated_at` | 时间。 |

#### `storybook_asset_references`

表示某张照片在一次专属创作里的业务引用。

| 字段 | 说明 |
| --- | --- |
| `id` | reference id。 |
| `workspace_id` | 空间。 |
| `creation_session_id` | 归属 session。 |
| `asset_id` | 原始上传文件。 |
| `kind` | `person` / `object` / `scene`。 |
| `display_name` | 用户命名，如“爸爸”“小汽车”“操场”。 |
| `usage` | `main_character` / `story_friend` / `name_only` / `story_object` / `background_scene` / `unused`。 |
| `status` | `awaiting_usage` / `awaiting_reference` / `awaiting_confirmation` / `ready` / `unused` / `revoked` / `failed`。 |
| `material_id` | 关联到 `CreationMaterial.id`，用于故事方向和大纲落点。 |
| `revoked_at` | 本次创作撤销时间，可为空。 |
| `revoked_by` | 撤销用户，可为空。 |
| `created_at` / `updated_at` | 时间。 |

#### `storybook_visual_references`

表示由真实照片生成的同画风参考。

| 字段 | 说明 |
| --- | --- |
| `id` | visual reference id。 |
| `workspace_id` | 空间。 |
| `asset_reference_id` | 归属素材引用。 |
| `generation_job_id` | 生成任务。 |
| `status` | `queued` / `generating` / `awaiting_confirmation` / `confirmed` / `failed` / `rejected`。 |
| `image_storage_key` | 生成参考图。 |
| `preview_url` | 可选，服务端响应时生成。 |
| `failure_reason` | 失败原因。 |
| `confirmed_at` | 用户确认时间。 |
| `confirmed_by` | 确认用户，可为空。 |
| `created_at` / `updated_at` | 时间。 |

### 3.2 权限、可见性与隐私

真实照片属于敏感资产，权限不能只依赖前端隐藏按钮。Phase 1 采用默认收紧策略。

#### Actor model

| 角色 | 说明 |
| --- | --- |
| 上传者 | 创建该 asset 的用户。 |
| 会话创建者 | 创建 `storybook_creation_session` 的用户。 |
| 空间管理员 | 当前 workspace 的 `SchoolAdmin`。 |
| 空间编辑者 | 具备绘本编辑权限的成员。Phase 1 默认不能接管他人创建的 session。 |
| 只读成员 | 可查看绘本但不能修改创作资产。 |

#### Permission matrix

| 操作 | 上传者/会话创建者 | 空间编辑者 | 空间管理员 | 只读成员 |
| --- | --- | --- | --- | --- |
| 查看本次 asset reference | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 查看原始照片预览 | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 上传照片 | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 更新用途/名称 | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 生成/确认视觉参考 | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 撤销本次引用 | 允许 | 仅本人创建的 session 允许 | 允许 | 拒绝 |
| 物理删除原始 asset | Phase 1 不开放 | Phase 1 不开放 | 后续隐私工单处理 | 拒绝 |

Phase 1 权限口径：

- 默认只有 session 创建者和 `SchoolAdmin` 可以操作创作资产。
- 其他编辑者即使同属 workspace，也不能查看原图、改用途或确认视觉参考，除非后续新增明确的协作授权字段。
- `SchoolAdmin` 可以查看和接管 workspace 内所有 session 的资产操作，但必须记录 actor。
- 所有 asset、asset reference、visual reference 的读写都必须同时校验 `workspace_id` 和 `creation_session_id`，不能只校验 asset id。

#### Privacy and retention rules

- 原始照片默认 `visibility_scope=creation_session`，只服务本次创作。
- Phase 1 不支持把上传照片沉淀为公共素材、空间素材或模板素材。
- `revoked` / `unused` 的 asset reference 不再参与任何后续 generation input。
- 原始 asset 若没有任何 active reference，可进入后台清理候选；清理周期建议作为配置项，默认 30 天。
- 已生成的视觉参考和最终绘本产物属于生成证据链的一部分，不因撤销本次引用立即物理删除；后续如需隐私删除，必须走独立隐私删除流程并记录影响范围。
- 删除 workspace 或后续删除儿童档案时，必须能按 `workspace_id` 和 generation input snapshot 追踪相关 asset/reference。
- 预览 URL 必须鉴权，不允许返回永久公开对象地址。

### 3.3 Upload goals

- 支持专属绘本创作中上传真实照片。
- 每次创作最多 5 张照片。
- 照片只用于本次创作，不自动进入公共素材库。
- 页面刷新后能恢复已上传、待确认、失败和已确认状态。
- 后端能在生成前判断照片是否满足门禁。

### 3.4 Accepted file rules

| 规则 | 建议 |
| --- | --- |
| 文件类型 | `image/jpeg`、`image/png`、`image/webp`。 |
| 单文件大小 | Phase 1 建议 10 MB 上限。 |
| 数量 | 每个 creation session 最多 5 个非 revoked/unused 引用。 |
| 图片尺寸 | 建议最短边不小于 512 px；过小允许上传但给 warning，是否阻断由产品确认。 |
| 安全 | 不信任前端 MIME，后端读取文件头校验。 |
| 命名 | 原文件名只用于显示，业务名使用 `display_name`。 |

### 3.5 推荐接口契约

#### 获取上传策略

```http
GET /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-upload-policy
```

响应：

```json
{
  "data": {
    "max_files": 5,
    "remaining_slots": 3,
    "max_file_size_bytes": 10485760,
    "accepted_content_types": ["image/jpeg", "image/png", "image/webp"]
  }
}
```

#### 上传照片

Phase 1 可以先使用后端直传 multipart，后续再切换预签名上传。

```http
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/assets
Content-Type: multipart/form-data
```

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 图片文件。 |
| `kind` | 是 | `person` / `object` / `scene`。 |
| `idempotency_key` | 是 | 防重复上传完成。 |

响应：

```json
{
  "data": {
    "asset_reference": {
      "id": "uuid",
      "asset_id": "uuid",
      "asset": {
        "id": "uuid",
        "status": "ready",
        "processing_message": null,
        "content_type": "image/jpeg",
        "byte_size": 2048000,
        "width": 1600,
        "height": 1200
      },
      "kind": "person",
      "display_name": "",
      "usage": null,
      "status": "awaiting_usage",
      "preview_url": "/api/workspaces/.../assets/.../preview",
      "visual_reference": null
    },
    "remaining_slots": 4
  }
}
```

说明：

- `asset.status` 表示文件上传与服务端处理状态。
- `asset_reference.status` 表示这张照片在本次创作里的业务状态。
- multipart 请求返回前应完成基础校验和预览可用性；若后续需要异步处理尺寸或安全扫描，则返回 `asset.status=processing` 和 `processing_message`，前端展示处理中并禁用用途确认。

#### 更新照片用途和名字

```http
PATCH /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
```

请求：

```json
{
  "kind": "person",
  "display_name": "爸爸",
  "usage": "main_character"
}
```

响应：

```json
{
  "data": {
    "asset_reference": {
      "id": "uuid",
      "kind": "person",
      "display_name": "爸爸",
      "usage": "main_character",
      "status": "awaiting_reference",
      "material_id": "m4",
      "visual_reference": {
        "id": "uuid",
        "status": "queued",
        "preview_url": null
      }
    },
    "session_update": {
      "requires_direction_refresh": true,
      "requires_outline_refresh": true
    }
  }
}
```

状态规则：

- 若视觉参考任务由后端自动创建，更新用途后可直接返回 `visual_reference.status=queued`。
- 若采用显式“生成参考”按钮，更新用途后返回 `visual_reference=null` 且 `asset_reference.status=awaiting_reference`，由前端再调用 `visual-reference:generate`。
- 两种模式二选一，Phase 1 推荐自动创建任务，减少用户额外操作。

规则：

- `usage=unused` 时不创建视觉参考，引用状态改为 `unused`。
- `display_name` 必须是用户可读名称，1 到 30 个字符。
- `kind=person` 且 `usage=main_character` 或 `story_friend` 时必须有 `display_name`。
- `kind=object` 建议提示“这是什么”；`kind=scene` 建议提示“这是哪里”。

#### 撤销本次照片引用

```http
DELETE /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
```

响应：

```json
{
  "data": {
    "id": "uuid",
    "status": "revoked",
    "remaining_slots": 2,
    "session_update": {
      "requires_direction_refresh": true,
      "requires_outline_refresh": true
    }
  }
}
```

规则：

- 只撤销本次创作引用，不物理删除已上传 asset。
- 未开始的视觉参考任务应取消。
- 已生成但未进入最终产物的参考图不再参与后续生成。
- 若 session 已经 `generating`，Phase 1 可以先阻断删除，并返回可读错误；后续 run 化后支持恢复动作。

恢复规则：

- 若 `asset.status=processing`，前端应恢复为“照片处理中”，禁用用途确认和视觉参考生成。
- 若 `asset.status=failed`，前端应展示失败原因，并允许用户撤销本次引用或重新上传。

### 3.6 状态映射规则

`storybook_visual_references.status` 是视觉参考任务的真实状态；`storybook_asset_references.status` 是面向创作流程的聚合状态。后端写入时必须保持以下映射，避免前端或生成门禁各自推断。

| asset reference status | 条件来源 | 前端含义 |
| --- | --- | --- |
| `awaiting_usage` | `usage is null` 且未撤销 | 需要选择用途。 |
| `unused` | `usage=unused` | 本次不使用，不阻断。 |
| `revoked` | `revoked_at is not null` | 已撤销，不阻断且不参与生成。 |
| `awaiting_reference` | 已选择使用，且无 active visual reference 或 visual reference 为 `queued/generating` | 等待同画风参考生成。 |
| `awaiting_confirmation` | active visual reference 为 `awaiting_confirmation` | 需要用户确认参考图。 |
| `ready` | active visual reference 为 `confirmed` | 可进入生成输入。 |
| `failed` | active visual reference 为 `failed` | 需要重试或改为不使用。 |

实现要求：

- 同一 `asset_reference_id` 只能有一个 active visual reference。
- 重新生成视觉参考时，旧的 `awaiting_confirmation` 参考应标记为 `rejected` 或非 active。
- 门禁只读取聚合后的 `asset_reference.status`，但该状态必须由 repository/application 根据 visual reference 真实状态计算或同步维护。

## 4. 生成门禁

Phase 1 将门禁分成“文字规划门禁”和“最终绘图门禁”，避免用户只是想先看故事方向时被图片处理长时间阻断。

| 接口 | 门禁粒度 | 规则 |
| --- | --- | --- |
| `directions:generate` | 软门禁 | 允许未确认视觉参考的照片参与文字规划，但响应必须在 `meta.warnings` 返回待处理引用，前端提示“制作前仍需确认参考”。 |
| `outline:generate` | 软门禁 | 允许先生成大纲；未确认照片可以作为待确认素材进入落点检查，但不能进入最终绘图。 |
| `storybook:generate` | 强门禁 | 所有选择“使用”的照片必须达到 `ready`，否则拒绝创建生成任务。 |

如果产品决定“确认视觉参考前连方向也不能生成”，可把软门禁升级为强门禁，但必须在产品文档中说明原因。当前后端方案默认采用软门禁 + 最终强门禁。

软门禁响应沿用现有 `Envelope` 风格，在 `meta.warnings` 中增加可读 warnings，避免接口各自发明顶层结构：

```json
{
  "data": {
    "status": "directions_ready"
  },
  "meta": {
    "warnings": [
      {
        "code": "visual_reference_pending",
        "message": "1 张照片还没有确认同画风参考，开始制作前需要处理。",
        "asset_reference_ids": ["uuid"],
        "next_action": "confirm_visual_reference"
      }
    ]
  }
}
```

### 4.1 使用照片的门禁

任一 `asset_reference.status` 为以下状态时，不能进入最终 `storybook:generate`：

| 状态 | 阻断原因 |
| --- | --- |
| `awaiting_usage` | 还未确认照片用途。 |
| `awaiting_reference` | 还未生成同画风参考，或生成任务仍在进行。 |
| `awaiting_confirmation` | 参考图已生成但用户还未确认。 |
| `failed` | 视觉参考失败，需要重试或改为不用。 |

不阻断的状态：

- `ready`
- `unused`
- `revoked`

### 4.2 错误响应

建议统一返回可行动错误：

```json
{
  "error": {
    "code": "visual_reference_required",
    "message": "先确认 1 张照片的同画风参考，再开始制作。",
    "details": {
      "blocking_asset_reference_ids": ["uuid"],
      "next_action": "confirm_visual_reference"
    }
  }
}
```

常用错误码：

| code | 使用场景 |
| --- | --- |
| `photo_limit_exceeded` | 超过 5 张。 |
| `unsupported_file_type` | 文件类型不支持。 |
| `file_too_large` | 文件过大。 |
| `asset_reference_not_found` | 引用不存在或不属于该 session。 |
| `asset_reference_revoked` | 引用已撤销。 |
| `visual_reference_required` | 已选择使用但未确认参考。 |
| `asset_processing` | 原始照片还在服务端处理中。 |
| `material_unplaced` | 锁定素材没有大纲落点。 |
| `session_not_editable` | 会话状态不能修改。 |

## 5. 与现有 `CreationMaterial` 的关系

当前 `CreationMaterial` 存在于 `materials_json`，用于方向、大纲和生成输入。照片引用不能替代它，而是应生成或关联一个 material。

建议规则：

1. 用户把照片标记为使用时，后端创建或复用一个 `CreationMaterial`。
2. `CreationMaterial.source = "asset_reference"`。
3. `CreationMaterial.label = display_name`。
4. `CreationMaterial.type` 映射：
   - `kind=person` -> `character`
   - `kind=object` -> `object`
   - `kind=scene` -> `scene`
5. `CreationMaterial.locked = true`。
6. `asset_reference.material_id` 指向该 material。
7. 用户改名时同步更新 material label，并让方向/大纲失效。
8. 用户撤销或改为不用时，material 不直接物理删除；可以标记引用状态，生成时过滤 `revoked/unused`。

## 6. 后端实施分期

### Phase 0：契约审计

目标：确认前端 UI 与现有后端字段差异。

任务：

- 梳理 `PersonalizedStorybookPage` 当前需要的 session 字段。
- 对照 `StorybookCreationSession` 响应，列出缺字段。
- 确认 `CreationMaterial.type` 可用枚举。
- 确认现有 `generation_jobs` 是否可复用视觉参考 job。
- 确认文件存储使用 `server/src/services/storage.rs` 的哪种路径。
- 确认 workspace 成员角色与 `require_editor_db` 是否足以覆盖资产操作权限。
- 确认预览 URL 的鉴权方式，禁止直接暴露永久公开地址。
- 确认软门禁 warnings 使用现有 `Envelope.meta` 承载。

验收：

- 输出字段差异清单。
- 不改业务代码也能说明前端每个动作对应哪个 API。
- 输出资产权限矩阵和隐私保留策略。
- 明确 Phase 1 只有 session 创建者和 `SchoolAdmin` 可操作资产。

### Phase 1：Schema 与模型

目标：让照片引用成为数据库真相。

任务：

- 新增 migration：
  - `storybook_assets`
  - `storybook_asset_references`
  - `storybook_visual_references`
- 新增 models：
  - `StorybookAsset`
  - `StorybookAssetReference`
  - `StorybookVisualReference`
  - 请求/响应 DTO。
- 新增 repository：
  - 创建 asset。
  - 创建/更新/撤销 reference。
  - 创建/更新/确认 visual reference。
  - 按 session 查询引用列表。
  - 根据 visual reference 真实状态计算 asset reference 聚合状态。

验收：

- migration 可重复执行。
- workspace/session 外键正确。
- 查询 session 能拿到 asset references。
- asset 默认 `visibility_scope=creation_session`。
- 同一 asset reference 最多一个 active visual reference。

### Phase 2：上传与引用 API

目标：前端可以真实上传照片并刷新恢复。

任务：

- 实现上传策略接口。
- 实现 multipart 上传接口。
- 校验数量、类型、大小。
- 生成预览 URL。
- 返回 `asset.status` 和 `processing_message`，区分上传完成与服务端处理完成。
- 实现引用更新和撤销。
- 更新 session 查询响应，包含 asset references。
  - session 恢复响应必须包含嵌套 `asset` 摘要。

验收：

- 上传 1 张照片后刷新页面仍能看到。
- 第 6 张照片返回 `photo_limit_exceeded`。
- 不支持格式返回 `unsupported_file_type`。
- 撤销后 remaining slots 正确恢复。
- `processing` 状态下前端不能确认用途。
- 非授权成员不能查看原图预览或修改引用。
- 刷新恢复时可看到 `asset.status` 和 `processing_message`。

### Phase 3：视觉参考任务

目标：照片必须变成同画风参考后才能进入生成。

任务：

- 新增 job_type，建议：`storybook_visual_reference`。
- 创建视觉参考 generation job。
- worker 生成参考图并写回 `storybook_visual_references`。
- 支持确认、重试、不使用。
- 失败时写入 `failure_reason`。
- 同步或计算 `asset_reference.status` 聚合状态。

验收：

- 标记使用照片后，状态进入 `awaiting_reference`。
- 视觉参考成功后，状态进入 `awaiting_confirmation`。
- 用户确认后，asset reference 进入 `ready`。
- 重新生成不会产生多个 active visual reference。
- 参考图预览 URL 需要鉴权。

### Phase 4：生成门禁与冻结输入

目标：生成时不会绕过照片确认。

任务：

- 在 `generate_directions`、`generate_outline`、`generate_storybook` 前加入 asset gate。
- `generate_directions` 和 `generate_outline` 默认采用软门禁，在 `meta.warnings` 返回待处理引用但允许继续。
- `generate_storybook` 采用强门禁，未确认参考时拒绝创建任务。
- `creation_storybook_generate` 的 `input_json` 加入：
  - `asset_references`
  - `visual_references`
  - `material_id` 关系
  - `confirmed_at`
  - `visibility_scope`
  - `retention_policy`
- 生成故事内容时过滤 `unused/revoked`。
- 当照片引用变化时，设置：
  - `requires_direction_refresh = true`
  - `requires_outline_refresh = true`

验收：

- 未确认视觉参考可以先看文字方向和大纲，但不能开始制作。
- 已确认照片出现在 generation input snapshot。
- 撤销照片后旧方向/大纲失效。

### Phase 5：来源书与批量定制

目标：在照片闭环稳定后再扩展来源书和批量。

任务：

- 来源书 snapshot。
- customization plan / run。
- run items。
- evidence。
- review 门禁。
- 批量对象主素材或 `name_only`。

验收：

- 源绘本只读。
- 批量部分失败不回滚成功项。
- review 能展示素材落点和证据。

## 7. 最小可交付垂直切片

第一条可上线验证的后端切片：

```text
创建 session
-> 上传 1 张照片
-> 填写“爸爸”
-> 标记为主角
-> 生成同画风参考
-> 确认参考
-> 生成 3 个方向
-> 生成 6 页大纲
-> 开始制作
```

这条切片不要求：

- 批量。
- 来源书定制。
- 页级 review。
- PDF evidence 门禁。
- 复杂图片安全扫描。

但必须保证：

- 页面刷新可恢复。
- 第 6 张照片被阻断。
- 未确认参考可以先看文字方向和大纲，但不能开始制作。
- 生成输入里能追踪照片引用和视觉参考。

## 8. 测试清单

### 8.1 单元测试

- `photo_limit_exceeded`。
- `unsupported_file_type`。
- `asset_reference_not_found`。
- `visual_reference_required`。
- `usage=unused` 不创建视觉参考。
- 改名同步 material label。
- 撤销引用后方向和大纲失效。
- visual reference 状态变化能正确映射 asset reference 聚合状态。
- `storybook:generate` 强门禁拒绝 `awaiting_confirmation`。
- `directions:generate` / `outline:generate` 软门禁返回 warning 但不阻断。

### 8.2 Repository 测试

- 创建 asset 和 reference。
- 同 session 查询 references。
- reference 不可跨 workspace/session 修改。
- confirmed visual reference 唯一。
- revoked reference 不计入 5 张上限。
- `visibility_scope=creation_session` 为默认值。
- 无 active reference 的 asset 可被后台清理查询选中。

### 8.3 API 测试

- 上传成功返回 `asset_reference`。
- 上传处理中返回 `asset.status=processing` 和 `processing_message`。
- 上传失败返回可读错误。
- 更新用途后返回 `awaiting_reference`。
- 确认参考后返回 `ready`。
- 未确认参考调用 `storybook:generate` 返回 `visual_reference_required`。
- 未确认参考调用 `directions:generate` 或 `outline:generate` 返回 `meta.warnings`。
- 无权限用户访问预览 URL 返回 403。
- 非创建者且非 `SchoolAdmin` 的编辑者修改他人 session asset reference 返回 403。

### 8.4 集成测试

- 完整最小切片跑通。
- 刷新恢复 session。
- 重复提交相同 idempotency key 不生成重复任务。
- 删除照片后再上传新照片。
- 生成 input snapshot 包含 asset reference、visual reference、权限/保留策略字段。
- revoked/unused 的照片不会进入 generation input。

## 9. 开工顺序建议

1. 先写 migration 和 models。
2. 再写 repository，并补 repository 测试。
3. 再写上传策略、上传、更新用途、撤销接口。
4. 再写视觉参考 job 的创建和确认接口。
5. 再把门禁接进现有 `storybook_creation` 主流程。
6. 最后让前端从 mock/local 状态切到真实 API。

不建议第一步就做：

- 批量 run。
- 来源书变化计划。
- review evidence。
- 图片模型 prompt 深度优化。

这些会把第一阶段拉得过宽，且不解决当前 UI 最大缺口。

## 10. 后端验收标准

- [ ] 上传照片后刷新页面不丢失。
- [ ] 本次创作最多 5 张有效照片。
- [ ] 照片用途、名字、状态都由服务端返回。
- [ ] 原始照片预览 URL 必须鉴权，不能公开暴露。
- [ ] Phase 1 只有 session 创建者和 `SchoolAdmin` 可以操作创作资产。
- [ ] 资产默认只用于本次创作，不进入公共或空间素材库。
- [ ] 上传完成和服务端处理完成有明确状态区分。
- [ ] session 恢复响应包含嵌套 `asset.status`、`processing_message`、`content_type`、`byte_size`、`width`、`height`。
- [ ] 已选择使用的照片必须确认同画风视觉参考。
- [ ] 未确认视觉参考时可以先看文字方向和大纲，但不能开始制作绘本。
- [ ] 软门禁 warnings 使用 `meta.warnings`，不新增非统一顶层响应结构。
- [ ] `asset_reference.status` 与 `visual_reference.status` 的映射由服务端统一维护。
- [ ] 视觉参考失败可重试或改为不使用。
- [ ] 撤销照片不会物理删除原始文件，但本次创作不再使用。
- [ ] revoked/unused 资产引用不进入 generation input。
- [ ] 资产引用变化会让方向和大纲失效。
- [ ] 生成任务输入中包含 confirmed asset references 和 visual references。
- [ ] 同一请求重复提交不会产生重复引用、重复视觉参考或重复绘本生成任务。
