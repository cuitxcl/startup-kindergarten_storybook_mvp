# 生图流程体验优化修改清单

## Problem

当前普通绘本生图流程功能完整，但体验偏“专业控制台”：页面一次性暴露太多字段、解释、复核信息和高级能力。老师或园所管理员进入“新建普通绘本”时，需要理解页面比例、画面风格、故事风格、故事框架、方案、角色、分页、参考图、生成任务元信息等概念，才会继续往下走。

这会带来三个问题：

- 用户还没看到绘本结果，就先进入大量配置和阅读。
- 生成主线被拆散，用户会觉得“我到底什么时候能看到图？”
- 系统能力很强，但页面层级让“创作一本绘本”这件事显得复杂。

本次优化目标不是删功能，而是把功能重新分层：默认路径更短、更少字、更像创作向导；高级控制保留，但默认收起。

## Target User

- 幼儿园老师：想快速生成一本可用于课堂共读、规则引导、情绪管理或家园沟通的绘本。
- 园所管理员：需要创建园所普通绘本模板，后续给老师复用、投稿或派生定制绘本。
- 早期试点使用者：对 AI 生成流程不一定熟悉，需要低认知负担地完成第一本绘本。

## Goal

把普通绘本生成从“五步配置和复核流程”调整为“三段式创作流程”：

1. 说清楚想做什么绘本。
2. 快速确认故事方向。
3. 一键进入图文生成，并在详情页继续精修。

成功体验应该是：

- 用户打开页面后，第一屏只看到最关键的问题和一个主按钮。
- 用户默认不需要理解 provider、schema、任务结构、参考图机制。
- 用户可以在 1-2 分钟内从需求进入生成结果，而不是先填完一整张配置表。
- 高级用户仍能展开控制画风、比例、故事框架、角色和分页文本。

## Non-goals

- 不重做后端生成能力。
- 不改变普通绘本、定制绘本、导出、分享、投稿的核心业务状态机。
- 不删除现有高级功能，只做信息架构和默认展示层级调整。
- 不在本阶段新增复杂 AI 聊天式创作入口。
- 不把所有插图编辑能力塞回新建向导，详情页仍是精修和交付中心。

## Product Direction

### 当前体验判断

当前页面的默认心智是：

> 填配置 -> 生成方案 -> 审方案 -> 生成角色 -> 审角色 -> 生成分页 -> 审分页 -> 去详情页继续生成插图。

目标心智应该变成：

> 告诉系统我要一本什么绘本 -> 看一眼方向 -> 生成图文草稿 -> 去详情页精修。

### 新的设计原则

- 主流程只保留一个明显主按钮。
- 默认只展示“用户要决定的内容”，不展示“系统如何工作的内容”。
- 解释文案从页面正文下沉到 tooltip、折叠区、空状态或错误恢复。
- 复核区默认展示摘要，不默认展示确认项列表。
- 高级设置默认收起，但必须可被发现。
- 生成中展示进度和当前正在做什么，不展示工程字段。
- 失败状态必须告诉用户下一步怎么恢复。

## User Flow

### Phase 1 新主流程

1. 用户进入 `/app/:workspaceId/storybooks/new`。
2. 页面第一屏展示“你想做一本什么绘本？”。
3. 用户填写或确认：
   - 绘本标题
   - 主题/目标
   - 年龄段
   - 使用场景
4. 可选：用户展开“高级设置”，调整：
   - 页数
   - 页面比例
   - 画面风格
   - 故事风格
   - 故事框架
5. 用户点击主按钮：`生成故事草稿`。
6. 系统生成方案，进入“故事草稿”页面。
7. 页面默认展示：
   - 标题和主题
   - 故事一句话摘要
   - 主要角色/道具摘要
   - 分页节奏摘要
8. 用户点击主按钮：`确认并生成图文`。
9. 系统自动串联：
   - 创建/保存普通绘本
   - 生成角色道具
   - 生成分页图文
   - 自动生成必要角色参考图
10. 完成后跳转详情页，并显示结果提示：
    - `图文草稿已生成，可以开始检查插图。`
11. 详情页负责：
    - 生成/重绘插图
    - 单页编辑
    - 老师复核
    - 标记可交付
    - 导出/分享/派生定制版

### 保留高级编辑路径

用户在“故事草稿”页面可以展开：

- `编辑故事方案`
- `查看角色和道具`
- `查看分页文本`
- `重新生成`

这些操作默认隐藏，不阻断普通用户继续生成。

### 当前具体痛点

- `NewStorybookPage.tsx`
  - `steps = ["需求", "绘本方案", "角色道具", "分页编辑", "预览导出"]` 暗示用户必须理解五个阶段。
  - `primaryLabels` 逐步强调系统内部产物：方案、角色、分页。
  - `handlePrimary` 分支多，体验上每一步都像单独任务。
  - step 2 和 step 3 默认进入编辑态，导致用户被带入大量文本编辑。
- `RequestStepForm.tsx`
  - 默认展示 9 类输入/选择/说明。
  - 页面比例、画面风格、故事风格、故事框架都在主路径。
  - 每个模块都有 hint，页面文字量被放大。
- `GenerationReviewBlock.tsx`
  - 默认显示 `老师审核`、provider、来源、任务、结构、隐私等系统元信息。
  - `复核工具` 虽然已折叠，但仍和主内容处于同级。
  - 无 `reviewContent` 时的 `确认项` 列表偏审核表，不像创作预览。
- `PlanReviewSummary.tsx`
  - 结构已经比原始确认项好，但仍包含“老师确认”“分页节奏”“角色与场景”等偏审核语言。

## Desired Information Architecture

### Route

仍使用：

- `/app/:workspaceId/storybooks/new`

### 新页面结构

#### 顶部

标题：

- `做一本班级绘本`

副标题：

- `写清楚主题，系统会先给出故事草稿，再生成图文。`

空间信息：

- 保留 `创建在 {workspace.name}`，但弱化为小字。

不要展示：

- provider 诊断，除非真实生成不可用或生成失败。
- “生成完成后可继续编辑”这类泛提示。

#### 进度条

把五步改为三步：

1. `需求`
2. `故事草稿`
3. `生成图文`

说明：

- 三步是用户心智，不必和后端任务一一对应。
- 角色、分页、参考图属于第 3 步内部进度，不暴露为顶层步骤。

#### Step 1：需求

页面主问题：

- `你想做一本什么绘本？`

默认字段：

- 绘本标题
- 主题/目标
- 年龄段
- 使用场景

默认值：

- 保留当前默认值：`一起玩小汽车`、`学会分享和轮流`、`4-5 岁`、`规则引导`。

主按钮：

- `生成故事草稿`

高级设置折叠区：

- 标题：`高级设置`
- 折叠说明：`页数、画面风格和故事框架`
- 内容：
  - 页数
  - 页面比例
  - 画面风格预设
  - 自定义画风文本
  - 故事风格
  - 故事框架

默认不要显示的文案：

- `页面比例会同时影响插图生成尺寸、详情预览和 PDF 导出页面。`
- `选中预设后可直接在文本框里微调，生成时会按这里的描述执行。`
- `故事风格决定情节基调...`
- `填写后，AI 会严格按你的框架展开分页...`

这些文案可以改为：

- tooltip
- 折叠区内的小字
- 帮助图标 title

#### Step 2：故事草稿

目标：

- 让用户快速判断方向是否对，而不是审核所有生成字段。

默认展示：

- 故事标题
- 教学目标/主题
- 一句话摘要
- 主要角色/道具，最多 4 个 chip
- 分页节奏，最多展示每页标题或 1 行短摘要

主按钮：

- `确认并生成图文`

次按钮：

- `调整需求`

更多操作折叠：

- `编辑故事草稿`
- `重新生成草稿`
- `查看生成详情`

不要默认展示：

- 来源
- 任务
- schema
- 隐私审计
- 完整角色要求
- 完整 review points

系统 meta 迁移：

- 放入 `查看生成详情` 折叠区。
- 折叠区标题不要叫 `老师审核`。
- 建议标题：`生成记录`。

#### Step 3：生成图文

目标：

- 给用户一个连续生成感，而不是让用户手动理解角色、分页、参考图。

点击 `确认并生成图文` 后进入此状态。

展示内容：

- 一个生成进度卡片。
- 当前阶段文字：
  - `正在整理角色和道具`
  - `正在规划分页图文`
  - `正在准备角色参考图`
  - `即将进入绘本详情`
- 阶段完成后打勾。

不要在这个阶段默认展示：

- RoleEditor
- PageEditor
- 角色参考图管理器
- 分页完整编辑器

生成成功：

- 自动跳转详情页。
- URL 保持现有详情页：`/app/:workspaceId/storybooks/:storybookId?result=plain`
- 详情页显示 toast 或 notice：
  - `图文草稿已生成，可以开始检查插图。`

生成失败：

- 停留在当前页面。
- 显示失败阶段和恢复动作。
- 主按钮变为：
  - `重试生成`
- 次按钮：
  - `返回故事草稿`
- 折叠详情：
  - 失败任务类型
  - 错误信息
  - 最近一次尝试时间

## Functional Requirements

### FR-1 简化需求输入

- 用户进入新建页时，默认只看到 4 个主字段。
- 高级设置默认折叠。
- 用户不展开高级设置也能生成完整绘本草稿。

### FR-2 故事草稿确认

- 生成方案后，页面展示故事草稿摘要。
- 用户能通过一个主按钮继续生成图文。
- 用户能返回修改需求。
- 用户能重新生成故事草稿。
- 用户能展开编辑故事草稿，但默认不展开。

### FR-3 串联生成

- 用户确认故事草稿后，系统自动生成角色、分页和必要参考图。
- 生成过程展示用户可理解的阶段。
- 成功后自动进入详情页。
- 失败后停留当前页，并提供重试和返回草稿。

### FR-4 高级功能保留

- 画风、故事风格、页面比例、故事框架仍可配置。
- 角色编辑仍可使用。
- 分页编辑仍可使用。
- provider/schema/privacy 等生成记录仍可查看。

### FR-5 不破坏恢复进度

- 如果用户通过 `?bookId=` 恢复未完成绘本，仍能恢复表单和生成输出。
- 恢复后应该映射到新的 3 步心智：
  - 只有需求 -> step 0
  - 有方案 -> step 1
  - 正在/已生成角色或分页 -> step 2 或跳转详情页，按状态判断
- 已失败任务仍显示恢复入口。

## Data Implications

本次优先不新增数据库字段。

需要确认现有数据是否足够支持：

- 根据已有 `generationJobs` 判断当前串联生成阶段。
- 根据 `storybook.status` 判断是否该留在向导或进入详情。
- 根据已有 `roles.referenceStatus` 判断参考图是否完成。

如果后续要更精确恢复串联进度，可以考虑新增但本阶段不做：

- `creation_flow_step`
- `creation_flow_phase`
- `last_creation_error`

## API Implications

优先复用现有 API。

当前应继续使用：

- 创建/更新 storybook
- 创建 generation job
- 查询 generation job
- 更新 roles
- 更新 pages
- 自动生成角色参考图相关接口

不要求新增 API。

可选后续优化：

- 新增一个后端 orchestration endpoint：
  - `POST /api/workspaces/:workspaceId/storybooks/:storybookId/generate-draft`
  - 一次串联角色、分页、参考图
- 但 Phase 1 建议先由前端串联，降低后端改动风险。

## Acceptance Criteria

### AC-1 第一屏简洁

- 在 1440px 宽桌面下，打开新建普通绘本页第一屏只展示：
  - 页面标题
  - 3 步进度
  - 4 个主字段
  - 一个主按钮
  - 一个高级设置折叠入口
- 第一屏不出现页面比例说明、provider、schema、角色参考图、分页编辑器。

### AC-2 高级设置可用

- 用户展开高级设置后，可以修改页数、页面比例、画面风格、故事风格和故事框架。
- 用户不展开高级设置，也可以完成生成。

### AC-3 故事草稿可快速确认

- 生成方案后，用户看到的是故事摘要，不是确认项清单。
- 页面默认不展示 `来源 / 任务 / 结构 / schema`。
- 用户可以点击 `确认并生成图文` 继续。
- 用户可以点击 `调整需求` 返回。
- 用户可以在折叠区查看生成记录。

### AC-4 串联生成不要求中途手动确认

- 点击 `确认并生成图文` 后，系统自动完成角色和分页生成。
- 用户不需要先进入 RoleEditor 再点击生成分页。
- 用户不需要先进入 PageEditor 再跳详情页。

### AC-5 生成进度可理解

- 生成过程中页面显示当前阶段。
- 阶段文案是用户语言：
  - 角色道具
  - 分页图文
  - 角色参考图
- 不默认展示 job type/provider/schema。

### AC-6 失败可恢复

- 任一阶段失败时，页面显示失败阶段。
- 有 `重试生成` 操作。
- 有 `返回故事草稿` 操作。
- 错误详情默认折叠。

### AC-7 详情页承接清楚

- 图文生成成功后进入详情页。
- 详情页显示简短成功提示。
- 用户能从详情页继续检查插图、重绘、标记可交付。

### AC-8 响应式

- 390px 移动端下，主字段单列展示。
- 主按钮在无需滚动太远的位置可见。
- 高级设置展开后不出现横向溢出。
- 3 步进度不挤压文字。

### AC-9 无回归

- `npm run build` 通过。
- 从绘本列表点击“新建普通绘本”能进入新流程。
- `?bookId=` 恢复已有草稿不崩溃。
- 已有详情页导出、分享、标记可交付逻辑不受影响。

## Open Questions

- 画面风格默认推荐 4 个具体选项是否需要产品确认？
- 是否允许“确认并生成图文”过程中用户离开页面？如果允许，是否需要更强的恢复提示？
- 自动生成角色参考图失败时，是否应该阻断详情页跳转？当前建议不阻断。
- 详情页是否应该自动开始生成第一页插图，还是只提示用户开始检查？当前建议不自动开始，避免不可控成本。

## Risks and Assumptions

- 风险：前端串联多个异步任务时，失败恢复比原来复杂。
  - 缓解：保留现有 retryJob 和 job 查询逻辑，失败时明确阶段。
- 风险：高级用户觉得控制少了。
  - 缓解：高级设置和编辑入口全部保留，只是默认收起。
- 风险：隐藏 provider/schema 后，调试不方便。
  - 缓解：生成记录折叠区保留完整信息。
- 风险：旧草稿恢复映射错误。
  - 缓解：实现时专门测试 `draft`、`plan_pending`、`roles_pending`、`editing`、失败任务恢复。

## Final UX North Star

用户不应该感觉自己在操作一个 AI 任务系统。

用户应该感觉：

> 我告诉系统一个教育目标，它帮我做出一本绘本草稿；我只需要检查方向、改几个关键点，然后进入详情页把插图和交付做好。
