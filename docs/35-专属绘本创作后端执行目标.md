# 专属绘本创作后端执行目标

> 依据文档：`docs/29-专属绘本创作统一实施说明.md`、`docs/30-专属绘本创作UI执行方案.md`、`docs/31-专属绘本创作后端落地执行方案.md`。  
> 使用场景：开启后端落地任务时直接引用本文，防止实现过程中范围漂移。  
> 最高目标：让专属绘本创作从“前端流程 + 临时状态”变成“后端可恢复、可鉴权、可门禁、可追踪、可交付”的业务闭环。

## 0. 可直接复制的后端任务启动语

```text
请以后端工程师视角，根据以下文档落地“专属绘本创作”的后端能力：

- docs/29-专属绘本创作统一实施说明.md
- docs/30-专属绘本创作UI执行方案.md
- docs/31-专属绘本创作后端落地执行方案.md
- docs/35-专属绘本创作后端执行目标.md

本任务目标：
让专属绘本创作具备后端真实状态、刷新恢复、权限校验、生成门禁、制作运行、交付证据和导出检查能力。前端只负责展示、输入和触发动作，不能依赖本地状态兜底。

执行要求：
1. 以 docs/29 为最高产品边界，以 docs/31 为后端落地依据。
2. 不重写现有 storybook_creation_sessions 直接创作主干；在现有能力上补齐真实照片、资产引用、视觉参考、来源书快照、制作运行和交付证据。
3. asset 只代表原始上传文件；asset_reference 才代表照片在本次创作里的业务引用。
4. 选择使用的照片必须生成并确认同画风 visual_reference；未确认、失败、撤销后仍被使用、没有故事落点的素材，不能进入最终制作。
5. directions:generate 和 outline:generate 可以对未完成照片返回 warnings，但 storybook:generate / customization run 必须强门禁。
6. 来源书定制必须冻结 source snapshot；源绘本更新后，旧计划必须返回 source_revision_conflict。
7. 批量定制必须按对象冻结 target_child_id、target_child_nickname、primary_material 或 name_only，不能共享一份主素材假设。
8. 每次制作必须有 run / run_item；输出绘本必须能反查本次运行、冻结输入和页级 evidence。
9. review / 导出前必须能从后端读取证据；evidence 缺失时导出应被阻断并返回可定位原因。
10. 补齐 migration、models、repository、application、controller、测试和 smoke 验证。

交付时必须说明：
- 新增或修改的数据表。
- 新增或修改的接口。
- 状态机和门禁规则。
- generation input snapshot 字段。
- 权限与隐私策略。
- 已运行的 cargo、API smoke、UI smoke 验证。
- 仍未完成的后续阶段。
```

## 1. Build Assumptions

- 现有直接创作主干已经存在，包括创建 session、恢复 session、生成方向、生成大纲和 `storybook:generate`。
- 本目标不是重构整条绘本生成链路，而是在现有主干旁补齐缺失的后端真相、恢复能力、门禁和证据链。
- `session`、`asset_reference`、`visual_reference`、`customization_plan`、`customization_run`、`run_item` 和 `evidence` 是业务事实来源。
- 前端本地状态只能保存未提交输入、展开状态和临时 UI 状态；不能作为刷新恢复、制作门禁或导出判断依据。
- 原始照片默认只属于当前创作，不进入公共素材库、空间素材库或模板素材。
- 用户撤销照片是撤销本次创作引用，不等于立即物理删除原始文件或已生成证据。
- 来源书定制永远不修改源绘本；每个定制产物都是独立输出绘本。

## 2. Dependency Chain

```text
产品边界确认
-> Schema / migration
-> Rust models / DTO
-> Repository 状态聚合
-> Application 门禁、幂等和快照
-> Controller / API
-> Generation job 写回
-> Session / review 查询响应
-> Smoke 与回归验证
```

实现顺序必须遵守：

- 先稳定数据模型和状态机，再接 API。
- 先有门禁和快照，再允许前端切到真实后端。
- 先跑通单本垂直闭环，再扩展来源书、批量、review evidence 和导出门禁。

## 3. Phase 1：照片资产引用与视觉参考闭环

目标：让“上传照片、命名、选择用途、生成同画风参考、确认参考、刷新恢复、最终制作门禁”全部由后端支撑。

必须交付：

- `storybook_assets`
- `storybook_asset_references`
- `storybook_visual_references`
- 上传策略、multipart 上传、预览鉴权、用途更新、撤销引用、视觉参考生成、视觉参考确认接口。
- session 恢复响应返回 `asset_references[]`，并包含嵌套 `asset` 和 `visual_reference`。
- `asset_reference.status` 由服务端聚合，至少覆盖 `awaiting_usage`、`unused`、`revoked`、`awaiting_reference`、`awaiting_confirmation`、`ready`、`failed`。
- `directions:generate` 和 `outline:generate` 对未确认视觉参考返回 warnings，但允许用户先看文字规划。
- `storybook:generate` 强阻断未确认、失败、仍待处理的素材。
- 最终 generation input snapshot 冻结 confirmed asset references、visual references、material_id、confirmed_at、visibility_scope、retention_policy。

验收口径：

- 上传照片后刷新页面不丢失。
- 每个 session 最多 5 张有效照片。
- 非图片、超大文件、第 6 张照片有稳定错误码。
- 原图和参考图预览必须鉴权。
- `unused` / `revoked` 不进入生成输入。
- 无照片的原有直接创作主流程不回归。

## 4. Phase 2：来源书计划与版本快照

目标：让“基于已有绘本创作专属版本”不再依赖前端静态计划，后端保存来源书快照、页级计划和变化原因。

必须交付：

- `customization_plan` 持久化。
- `source_snapshot` 冻结来源绘本 id、标题、状态、更新时间、页数、页 id、页面摘要和可定制性判断。
- 页级 `page_plan`，覆盖保持、尽量保持、对象版本、必须重绘、可选重绘和重绘原因。
- 单人定制冻结 `target_child_id`、`target_child_nickname`、`primary_material` 或 `name_only`。
- 来源绘本更新后，旧计划调用制作时返回 `source_revision_conflict`，并给出 `next_action=refresh_source_plan`。
- 输出绘本能反查来源书、计划摘要、目标对象和主素材。

验收口径：

- review 页刷新后仍能展示本次定制计划摘要。
- 来源绘本更新后不能继续使用旧计划制作。
- 单人输出能追溯目标对象、来源快照和主素材。
- 新增素材只影响被定制对象、被选中的变化页和服务端判定必须重绘的关键页。

## 5. Phase 3：Run、Run Item 与批量恢复

目标：把“正在制作、部分失败、取消、重试、离开恢复”从前端本地状态转移到后端。

必须交付：

- `customization_runs`
- `customization_run_items`
- 同一计划版本只能有一个 active run，重复点击返回同一 run。
- 单人 run 只有一个 item；批量 run 每个对象一个 item。
- 每个 item 独立记录 `queued`、`running`、`succeeded`、`failed`、`canceled`、`retrying`。
- 批量定制按对象冻结 `target_child_id`、`target_child_nickname`、`primary_material` 或 `name_only`。
- 批量部分失败不回滚成功项；失败项可单项重试或放弃。
- 前端刷新后可按 `run_id` 恢复制作进度和批量结果。

验收口径：

- 连续点击开始制作不会产生重复绘本或重复任务。
- 批量成功项可进入 review，失败项不阻塞成功项交付。
- 每本批量输出绘本都有自己的对象快照和主素材选择。
- 运行中取消或失败后，前端能拿到明确恢复动作。

## 6. Phase 4：Review Evidence 与导出门禁

目标：让“修改与交付”页能解释本次输出用了哪些素材、哪些页被改、哪些证据缺失，并在导出前由后端做最终门禁。

必须交付：

- 产物详情返回定制计划摘要、运行记录和 run item 快照。
- 页级 evidence：来源页、目标页、文字变化、素材落点、视觉参考、重绘原因和实际读取的冻结输入。
- 文本修改、页级重绘、满意状态由后端保存。
- 导出前检查 evidence 完整性。
- evidence 缺失时返回可定位的问题页、缺失字段和修复动作。
- 导出成功时能追溯到对应 `run_id`、`run_item_id` 和 generation input snapshot。

验收口径：

- review 页面刷新后仍能看到本次定制计划、运行记录和页级证据。
- 用户能看到素材落点、变化原因和原书对照。
- evidence 不完整时不能导出，并返回可读错误。
- 普通绘本导出不受定制 evidence 门禁误伤。

## 7. 不在当前后端目标内

- 公共素材库沉淀。
- 人脸识别、相似度评分或身份承诺。
- 用户编辑 prompt、权重、模型或图像参数。
- 商业化付费、额度、账单。
- 大规模异步队列治理平台化。
- 隐私删除全链路自动擦除。

这些可以进入后续工程目标，但不能阻塞专属绘本创作主链路落地。

## 8. Validation Checkpoints

后端交付前至少运行：

```bash
cargo fmt --all --check
cargo check --features db
cargo test --features db
scripts/smoke-storybook-creation-assets.sh
scripts/smoke-storybook-creation-ui.sh
```

如果某条命令无法运行，交付说明必须写明原因、影响范围和替代验证。

最小 smoke 必须覆盖：

- 创建专属绘本 session。
- 上传 1 张人物照片并命名。
- 生成并确认 visual reference。
- 刷新恢复 session。
- 未确认 visual reference 时 `storybook:generate` 被阻断。
- 已确认 visual reference 后 `storybook:generate` 成功入队。
- 来源书计划包含 `source_snapshot`。
- 来源书变更后旧计划返回 `source_revision_conflict`。
- 批量定制每个输出绘本冻结自己的 `target_child_id` 和 `primary_material`。
- review 页能读取 run / run item / page evidence。
- evidence 缺失时导出被阻断，普通绘本导出不受影响。

## 9. Main Implementation Risks

- 前端本地状态和后端真相并存，容易导致刷新后状态不一致。
- `asset` 与 `asset_reference` 混用，会让撤销、恢复、门禁和证据链不可靠。
- 只做 API 返回、不做 generation input snapshot，会导致最终绘本无法追溯素材来源。
- 来源书定制如果没有 `source_snapshot`，源绘本更新后会继续使用过期计划。
- 批量定制如果不按对象冻结素材，可能把一个孩子的主素材错误套到其他孩子身上。
- run 和 run item 如果没有幂等约束，连续点击会产生重复任务和重复绘本。
- evidence 如果只由前端展示拼装，导出和审计无法判断本次生成实际读取了什么。

## 11. 给后端任务使用的执行目标

如果需要在 Codex 或后端任务里开启一个明确目标，建议直接使用下面这段。它比第 0 节更短，更适合作为任务目标标题和首条指令。

```text
目标：根据 docs/29、docs/30、docs/31 和 docs/35，落地“专属绘本创作”后端闭环。

后端必须把专属绘本创作从前端临时状态改造成服务端业务真相，覆盖照片资产、视觉参考、来源书快照、制作运行、页级证据和导出门禁。实现时不要重写已有直接创作主干，而是在现有 storybook_creation_sessions、generation_jobs、storybooks、delivery/share/export 能力上补齐缺失的数据模型、接口、门禁和 smoke 验证。

第一轮交付优先级：
P0：保证照片资产引用与视觉参考闭环真实可恢复，包括上传、命名、用途、撤销、预览鉴权、视觉参考生成/确认、session 恢复和最终生成强门禁。
P1：保证来源书定制可追溯，包括 source_snapshot、page_plan、source_revision_conflict、单人目标对象和主素材冻结。
P2：保证制作运行可恢复，包括 customization_run、run_item、批量对象独立快照、重复点击幂等、失败重试和放弃。
P3：保证交付证据可检查，包括 review evidence、generation input snapshot、导出/分享/公开导出前 evidence 门禁。

交付判断：
- 所有业务状态以后端为准，前端刷新后不能丢失关键流程状态。
- 所有会进入生成的素材必须有 asset_reference_id 和 confirmed visual_reference。
- 所有输出绘本必须能反查本次 run/run_item、冻结输入、来源计划和页级 evidence。
- evidence 缺失时必须阻断导出，并返回可定位原因；普通绘本导出不能被误伤。
- 必须补 migration、models、repository、application、controller 和 smoke；交付说明必须列出已运行验证。
```

## 12. 推荐开工切片

为了避免一次任务过大，后端可以按下面切片推进。每个切片都必须保持系统可运行，不能把半成品状态交给前端兜底。

| 切片 | 目标 | 完成信号 |
| --- | --- | --- |
| Slice 1 | 照片资产表、引用表、视觉参考表和基础 DTO | migration 可跑；session 查询能返回空的 `asset_references[]`。 |
| Slice 2 | 上传、用途更新、撤销、预览鉴权 | 前端刷新后能恢复照片列表；第 6 张、非法类型、越权预览被阻断。 |
| Slice 3 | 视觉参考生成/确认和直接创作门禁 | 未确认参考不能 `storybook:generate`；确认后 generation input 冻结引用。 |
| Slice 4 | 来源书计划和 source snapshot | 旧计划遇到源书更新返回 `source_revision_conflict`。 |
| Slice 5 | run / run item 和批量恢复 | 重复点击不产生重复绘本；失败项可重试或放弃。 |
| Slice 6 | review evidence 与导出门禁 | review 能解释证据；缺证据导出被阻断，普通绘本不受影响。 |

## 13. 后端不要偏航的边界

- 不做公共素材库、跨作品照片库或模板素材沉淀。
- 不做人脸识别、相似度判断或“像不像”的自动承诺。
- 不开放 prompt、模型参数、权重调节。
- 不把视觉参考当成普通贴图直接贴进绘本。
- 不让前端用本地 mock 状态替代后端状态机。
- 不把失败、取消或已撤销的素材继续写进新的 generation input。
