# 专属绘本创作后端开工目标

> 依据：`docs/29-专属绘本创作统一实施说明.md`、`docs/30-专属绘本创作UI执行方案.md`、`docs/31-专属绘本创作后端落地执行方案.md`、`docs/35-专属绘本创作后端执行目标.md`。  
> 用途：开启后端落地任务时直接引用，作为后端工程师的执行目标和验收边界。  
> 一句话目标：把“专属绘本创作”从前端临时流程落成后端业务闭环，确保状态可恢复、素材可追踪、生成有门禁、产物可审计、交付可验收。

## 1. 后端任务启动语

```text
请以后端工程师视角，根据 docs/29、docs/30、docs/31 和 docs/35 落地“专属绘本创作”后端闭环。

本任务不是重写现有绘本生成主干，而是在已有 storybook_creation_sessions、generation_jobs、storybooks、导出/分享能力上补齐：
- 照片资产与本次创作引用。
- 同画风视觉参考生成与确认。
- 直接创作最终生成门禁。
- 基于已有绘本的 source snapshot 与 page_plan。
- 单人/批量 customization run 与 run item。
- generation input snapshot、review evidence 与导出门禁。

后端必须成为业务真相。前端只负责输入、展示和触发动作，不能用本地状态兜底刷新恢复、制作门禁、证据展示或导出判断。
```

## 2. Build Assumptions

- 直接创作主干已经存在：创建 session、恢复 session、生成方向、生成大纲和开始生成。
- 本阶段优先补齐后端缺失能力，不做大范围重构。
- `asset` 只表示原始上传文件；`asset_reference` 才表示照片在本次创作中的业务引用。
- 所有被使用的照片必须先生成并确认同画风 `visual_reference`，才能进入最终制作。
- 源绘本永远只读；专属版本必须生成独立输出绘本。
- 输出绘本必须能反查本次 run、run item、冻结输入、来源计划和页级 evidence。

## 3. Dependency Chain

```text
Schema / migration
-> Rust models / DTO
-> Repository 聚合查询
-> Application 状态机、门禁、幂等、快照
-> Controller / API
-> Generation input snapshot
-> Review evidence / export gate
-> API smoke / UI smoke / cargo 验证
```

实现顺序必须先稳定数据与状态机，再接接口；先有门禁和快照，再允许前端依赖真实后端。

## 4. Phase 1：照片资产引用与视觉参考闭环

目标：上传照片、命名、选择用途、生成同画风参考、确认参考、刷新恢复和最终生成门禁全部由后端支撑。

必须交付：

- `storybook_assets`
- `storybook_asset_references`
- `storybook_visual_references`
- 上传策略、multipart 上传、预览鉴权、用途更新、撤销引用、视觉参考生成、视觉参考确认接口。
- session 恢复响应返回 `asset_references[]`，包含嵌套 `asset` 与 `visual_reference`。
- `directions:generate`、`outline:generate` 可对未完成照片返回 warnings。
- `storybook:generate` 必须强阻断未确认、失败、撤销后仍被使用、没有落点的照片素材。
- 最终 generation input snapshot 冻结 `asset_reference_id`、`visual_reference_id`、用途、名称、落点和确认时间。

完成信号：

- 刷新页面后照片状态不丢失。
- 第 6 张照片、非法图片、越权预览被阻断。
- `unused` / `revoked` 不进入新的生成输入。
- 无照片的直接创作主流程不回归。

## 5. Phase 2：来源书计划与版本快照

目标：基于已有绘本创作专属版本时，服务端保存真实变化计划，不能由前端静态拼装。

必须交付：

- `customization_plan`。
- `source_snapshot`：来源绘本 id、标题、状态、更新时间、页数、页 id 和页面摘要。
- `page_plan`：保持原样、对象版本、必须重绘、可选重绘、尽量保持和重绘原因。
- 单人定制冻结 `target_child_id`、`target_child_nickname`、`primary_material` 或 `name_only`。
- 源绘本更新后，旧计划制作返回 `source_revision_conflict`，并给出 `next_action=refresh_source_plan`。

完成信号：

- review 刷新后仍能展示来源书、目标对象和变化计划。
- 源绘本更新后不能继续使用旧计划。
- 新增素材只影响被定制对象、被选变化页和服务端判定必须重绘的关键页。

## 6. Phase 3：Run、Run Item 与批量恢复

目标：把制作进度、失败、取消、重试和离开恢复转移到后端。

必须交付：

- `customization_runs`
- `customization_run_items`
- 同一计划版本只能有一个 active run，重复点击返回同一 run。
- 单人 run 只有一个 item；批量 run 每个对象一个 item。
- 每个 run item 独立记录对象快照、主素材选择、状态、错误和输出绘本。
- 批量部分失败不回滚成功项；失败项可单项重试或放弃。
- 用户撤销照片后，未开始和后续任务不得继续使用该照片；旧计划必须返回 `asset_revoked` 或要求重新预览。

完成信号：

- 连续点击开始制作不会产生重复绘本或重复任务。
- 批量成功项可进入 review，失败项不阻塞成功项交付。
- 每个批量输出绘本都有自己的对象快照和主素材证据。

## 7. Phase 4：Review Evidence 与导出门禁

目标：交付页能说明本次输出用了什么素材、哪些页变化、哪些证据缺失，并由后端决定能否导出。

必须交付：

- 产物详情返回定制计划摘要、run、run item 和冻结输入。
- 页级 evidence：来源页、目标页、文字变化、素材落点、视觉参考、重绘原因和实际读取的输入。
- 文本修改、页级重绘、满意状态后端保存。
- 导出、分享、公开导出前检查 evidence 完整性。
- evidence 缺失时返回问题页、缺失字段和修复动作。

完成信号：

- review 页面刷新后证据不丢失。
- 用户能看到素材落点、变化原因和原书对照。
- evidence 不完整时导出被阻断；普通绘本导出不被误伤。

## 8. 不在本轮目标内

- 公共素材库或跨作品照片库。
- 人脸识别、身份识别、相似度评分或“像不像”自动承诺。
- prompt、模型参数、权重调节。
- 商业化付费、额度、账单。
- 隐私删除全链路自动擦除。

## 9. Validation Checkpoints

交付前至少运行：

```bash
cargo fmt --all --check
cargo check --features db
cargo test --features db
scripts/smoke-storybook-creation-assets.sh
scripts/smoke-storybook-creation-ui.sh
```

最小 smoke 必须覆盖：

- 创建专属绘本 session。
- 上传 1 张照片并命名。
- 生成并确认 visual reference。
- 刷新恢复 session。
- 未确认 visual reference 时最终生成被阻断。
- 已确认 visual reference 后最终生成成功入队。
- 来源书计划包含 `source_snapshot`。
- 来源书变更后旧计划返回 `source_revision_conflict`。
- 批量定制每个输出绘本冻结自己的对象和主素材。
- review 能读取 run / run item / page evidence。
- evidence 缺失时导出被阻断，普通绘本导出不受影响。
