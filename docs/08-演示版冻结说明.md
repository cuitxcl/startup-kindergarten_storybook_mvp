# Kindleaf 本地演示版冻结说明

## 1. 冻结结论

当前项目已经达到“本地可演示闭环”标准，可以先冻结为演示版。

冻结口径不是生产上线，而是证明以下主路径能在本地真实 API + PostgreSQL 环境中跑通：

- 老师登录系统。
- 进入个人空间或园所空间。
- 查看工作台。
- 创建、编辑普通绘本。
- 维护儿童档案。
- 基于普通绘本生成单个儿童的定制绘本，并支持批量选择多个儿童派生独立定制副本。
- 生成插图文件：演示环境可使用 mock provider 做 quota-free 验收；真实生图模型已统一为字节跳动 Seedream，并具备 fake provider、真实 Seedream 试运行脚本、DeepSeek+Seedream 组合验收脚本和人工短绘本一致性复核记录。
- 导出带分页插图的本地基础 PDF 文件。
- 创建和撤回分享链接。
- 园所投稿、隐私确认、平台审核上架。
- 从绘本市场复制模板回当前空间。
- 家长资料链接创建、公开提交、确认入档。
- 园所生成队列恢复。
- 用户/空间存储限额：登录态图片生成和 PDF 导出会同时检查 workspace 容量和发起人的用户个人容量，园所空间导出也会计入发起人个人额度；公开分享导出只计入 workspace 容量。
- 平台运营 readiness：数据库结构检查会确认生成任务和导出任务的 `created_by` 容量归属字段存在，避免漏跑容量相关 migration 后仍误判为可演示。

最近一次完整验收命令：

```sh
CHECK_SMART_RUN_FULL=true ./scripts/check-smart.sh auto
```

演示交接前也可运行 `./scripts/check-smart.sh full`、`./scripts/check-smart.sh demo` 或 `./scripts/smoke-all.sh`；推荐优先使用 `CHECK_SMART_RUN_FULL=true ./scripts/check-smart.sh auto`，它会按智能调度先跑 fast check，再固定跑完整 API + UI smoke。

## 2. 演示环境启动

启动 PostgreSQL：

```sh
docker compose up -d postgres
```

运行 migration：

```sh
cd server
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
  cargo run -p migration -- up
```

写入演示数据：

```sh
cd server
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
  cargo run --features db -- db seed
```

启动后端：

```sh
cd server
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
KINDLEAF_DEMO_SEED=1 \
KINDLEAF_GENERATION_PROVIDER=composite \
KINDLEAF_COST_BUDGET_WARNING_PERCENT=80 \
  cargo run --features db -- start -a
```

启动前端：

```sh
cd frontend
npm run dev:api
```

## 4. 推荐演示路径

### 4.1 园所管理员主线

1. 登录 `lin@example.com / demo`。
2. 进入 `星星幼儿园`。
3. 打开园所工作台，查看今日重点和绘本生产入口。
4. 创建普通绘本。
5. 在绘本详情中编辑文字、角色和页面。
6. 生成插图。
7. 标记可交付。
8. 导出 PDF。
9. 创建分享链接。
10. 进入园所管理，创建老师邀请、管理班级、查看投稿。
11. 将普通绘本投稿到市场。
12. 在平台运营后台审核上架。
13. 回到市场复制模板到当前空间。

### 4.2 儿童定制主线

1. 进入儿童档案页。
2. 新增儿童档案，填写称呼、年龄段、兴趣、特质和关注点。
3. 从普通绘本进入定制绘本流程。
4. 选择儿童。
5. 生成定制方案。
6. 生成定制副本，成功后系统自动打开生成结果详情。
7. 在定制绘本详情中检查内容、标记可交付、导出或分享。

### 4.3 家长资料链接主线

1. 园所管理员进入儿童档案页。
2. 选择班级范围。
3. 生成家长资料链接。
4. 打开公开链接，提交孩子资料。
5. 回到儿童档案页，在待确认队列确认入档。
6. 确认后的儿童档案继承来源班级。
7. 可撤回链接或批量停用当前班级可填写链接。

### 4.4 园所老师边界

1. 切换到老师空间。
2. 老师只能看到授权班级内的儿童档案。
3. 老师不能进入园所管理页。
4. 老师查询生成任务时，原始输入会脱敏。

## 5. 已知限制

这些限制不阻碍本地演示，但会影响真实试点或上线质量：

- 本地演示仍可使用 mock/fake provider 做不消耗额度的稳定验收；真实演示可切到 DeepSeek + Seedream 组合 provider。
- DeepSeek 文本 provider 已有 fake smoke、真实试运行脚本、HTTP 边界、输出结构校验和脱敏审计；后续真实试点仍需收口配额、降级策略、告警和提示词质量持续优化。
- 图片生成已统一到字节跳动 Seedream，已有 mock PNG、fake Seedream smoke、真实 Seedream 试运行脚本和 DeepSeek+Seedream 组合验收脚本；Seedream 输出写入前会拒绝非 PNG 内容，角色参考图可作为分页插图参考输入。图片文件读写已抽出可配置 storage service，但图片审核、对象存储和生产文件生命周期还未生产化。
- PDF 导出已有带分页插图的本地基础 PDF 文件和权限下载，分页插图会按比例居中适配画框，避免方图/竖图被拉伸。PDF 文件读写已抽出可配置 storage service；但专业排版模板、字体嵌入和对象存储还未生产化。
- 邮件/短信邀请尚未接入，当前邀请链接仍通过页面展示和复制。
- 平台审核、隐私脱敏和内容安全还是基础版本。
- 商业化额度、套餐、账单和支付未实现。
- 当前演示依赖本地 PostgreSQL、Docker、Chrome headless 和本地端口。

## 7. 下一阶段边界

演示版冻结后，不建议继续扩大 mock 功能范围。

下一阶段应集中做真实生成质量打磨和试点准备：

1. 真实文本生成质量：故事方案、角色设定、分页图文、定制方案的提示词和人工验收样例。
2. 真实插图生成质量：角色/道具一致性、图片审核、对象存储和文件生命周期。
3. PDF 排版升级：专业排版模板、字体嵌入、对象存储和文件生命周期。
4. 邮件邀请：老师邀请和通知。
5. 试点安全：儿童资料隐私、投稿脱敏、操作审计、备份恢复。

判断标准也应从“页面能不能点”切换为：

- 生成结果是否可用。
- 数据是否可信。
- 异常是否可恢复。
- 权限是否不会越界。
- 运营是否能追踪和处置问题。

真实生成接入细节见 `docs/09-真实生成能力接入说明.md`。
