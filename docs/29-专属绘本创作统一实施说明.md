# 专属绘本创作统一实施说明

> 状态：当前唯一产品与全栈实施基线。  
> 适用角色：产品、UI/UX、前端、后端、测试。  
> 关联文档：20 号 UI 方案仅保留为页面结构、文案语气和视觉密度参考；23 至 28 号文档定义后端细节；本文定义统一产品边界、前后端改造范围和上线顺序。若 20 号文档与本文冲突，以本文为准。

## 1. 产品决定

“创建专属故事”和“基于已有绘本私人定制”不再作为两个产品能力对外表达，统一称为 **专属绘本创作**。

它们只有故事起点不同：

| 起点 | 用户已经确定的内容 | 系统需要补齐的内容 |
| --- | --- | --- |
| 从想法开始 | 一句故事想法、对象、想留下的元素 | 故事方向、6 页走向、封面和插图。 |
| 基于已有绘本 | 已认可的故事主线、页数和阅读节奏 | 对象级变化范围、重绘范围和定制副本。 |

两条路径的共同价值是：用户给一本绘本指定对象，并选择性上传人物、玩具、物品、宠物或场景照片。系统将照片转为符合绘本画风的视觉参考，再将确认的参考真实带入封面、文本、插图和后续重绘。

照片不是贴图素材，也不是独立的“AI 生图”功能。它是一本专属绘本的受控视觉输入。

视觉参考包括两类：

| 类型 | 来源 | 用途 |
| --- | --- | --- |
| 角色参考 | 人物、宠物等会作为故事角色出现的照片 | 约束封面和内页的角色外观一致性。 |
| 道具/场景参考 | 玩具、作品、物品、常去地点等照片 | 约束故事中的物品、场景氛围或关键画面元素。 |

所有确认照片都必须先生成同画风视觉参考，再进入计划和生成输入。原始照片不得直接作为封面或内页贴图，也不得只停留在 UI 展示层。

## 2. 范围与非目标

### 2.1 本期必须实现

- 一个统一的“专属绘本创作”入口，支持两种起点。
- 对象、文字素材和可选照片在同一个“对象与素材”页面完成。
- 人物照片的角色身份确认和同画风角色参考确认。
- 玩具/物品照片的自然语言用途确认和同画风道具参考确认。
- 直接创作的 3 个方向 -> 选中方向 -> 6 页走向。
- 派生定制的保持/变化/重绘预览，及可选页“尽量保持”重算。
- 统一制作进度、离开恢复、失败重试、素材撤销和修改交付。
- 批量定制仅在已有绘本起点提供，每位对象独立确认主素材。

### 2.2 不在本期做

- 不把人物照片识别为真实身份，不保存人脸身份结论。
- 不提供用户编辑 prompt、权重、模型或图像参数。
- 不在直接创作入口支持批量定制。
- 不改变已有普通绘本创建向导的业务语义和历史链接。
- 不做跨作品照片素材库；照片只属于当前会话或计划。

## 3. 信息架构与路由

### 3.1 对外名称

| 旧名称 | 新名称 | 处理 |
| --- | --- | --- |
| 创建专属故事 | 创建专属绘本 | 修改仪表盘、页面标题和按钮文案。 |
| 生成定制绘本/私人定制 | 基于已有绘本创作专属版本 | 作为同一能力的第二起点。 |
| 普通绘本创建 | 创建普通绘本 | 保留原有入口和向导。 |

### 3.2 路由策略

| 路由 | 目标 | 迁移处理 |
| --- | --- | --- |
| `/app/:workspaceId/storybooks/new` | 普通绘本创建 | 保持现有行为，避免已有链接和班级共读流程回归。 |
| `/app/:workspaceId/storybooks/personalized/new` | 专属绘本创作入口 | 保留 URL，页面标题改为“创建专属绘本”，加入两种起点。 |
| `/app/:workspaceId/storybooks/:storybookId/customize` | 基于已有绘本的兼容入口 | 重定向到统一页面，并带 `sourceStorybookId`；不再保留独立向导状态。 |
| `/app/:workspaceId/storybooks/:storybookId/review` | 专属产物修改与交付 | 仅定制产物使用，可带 `run_item_id` 定位本次输出和证据。 |

仪表盘中的“创建普通绘本”继续指向 `/storybooks/new`；“创建专属绘本”指向 `/storybooks/personalized/new`。普通绘本详情中的定制按钮指向统一入口并传入来源书；专属产物详情优先进入 review 子视图。用户不需要理解旧页面之间的技术区别。

## 4. 用户流程

```text
进入创建专属绘本
-> 选择起点：从想法开始 / 基于已有绘本
-> 对象与素材
-> 故事预览
-> 制作
-> 修改与交付
```

### 4.1 起点 A：从想法开始

1. 用户填写至少 8 个有效字符的故事想法，可选填写对象称呼。
2. 系统保存服务端草稿，轻量识别不超过 3 个候选元素；用户可增删锁定文字素材。
3. 用户可选上传最多 5 张真实照片，确认每张照片的用途或选择不使用。
4. 点击“看看故事怎么讲”后，系统生成恰好 3 个故事方向。
5. 用户选择一个方向；所有锁定文字素材和已确认视觉参考必须有明确落点。
6. 系统生成 6 页故事走向。用户可补充某一页，只有该页的文字、画面描述和素材落点重算。
7. 用户确认后创建一次制作运行，生成独立绘本。

### 4.2 起点 B：基于已有绘本

1. 用户选择一本普通绘本。列表明确显示可定制、仍在制作或需要处理的原因。
2. 页面展示来源摘要：保留故事主线、页数和阅读节奏；不再次让用户输入故事想法。
3. 用户选择一个对象，或进入“为多人制作”。可选添加文字或照片素材；批量模式下每个对象的主素材必须独立确认。新增素材只允许影响被定制对象、被选中的变化页和服务端判定必须重绘的关键页，不能默认重写源绘本主线、页数和阅读节奏。
4. 系统生成真实变化计划：保持不变、变成对象版本、必须重绘的关键页和可选变化页。
5. 用户可对可选页选择“尽量保持这一页”；服务端重新计算是否仍存在图文冲突、重绘范围和预计时间。
6. 单人直接确认制作。批量时，每位对象必须确认一项主素材，或明确选择“仅使用称呼”。
7. 每位对象生成一本独立副本；源绘本不被修改，批量部分失败不回滚成功项。批量完成后进入批量结果页，按对象展示成功、失败、需补素材和已排除状态；成功对象可单独进入 `/storybooks/:storybookId/review` 检查、重绘和导出，失败对象只能补素材、重试或放弃，不阻塞其他对象交付。

### 4.3 共同的照片行为

| 用户素材 | 用户确认 | 系统行为 |
| --- | --- | --- |
| 人物照片 | 主角 / 故事里的朋友 / 只保留名字 / 不使用 | 前两者后台生成角色参考，故事预览内要求确认。 |
| 玩具、物品、宠物照片 | 把它写进故事 / 不使用 | 生成同画风道具参考，显示计划中的页级落点。 |
| 场景照片 | 用作故事场景 / 不使用 | 生成同画风场景参考，仅影响计划指定页面。 |

用户确认使用照片后，本次创作必须先生成 `asset_reference_id`，后续计划、删除、恢复、证据和任务调度都以 `asset_reference_id` 为业务引用对象，不能直接操作原始 `asset_id`。确认的素材引用必须进入冻结计划，并在计划中返回 `asset_reference_id`、`visual_reference_id`、参考类型、预计出现位置和未覆盖原因。若存在 `unplaced_assets`，前端不能显示“开始制作”，只能提示用户重新预览、撤销素材引用或改为不使用。

用户删除照片时，实际动作是撤销本次创作里的素材引用，而不是删除原始素材文件。UI 立即移除该引用，排队和后续重绘停止使用；已经开始的单次外部绘制不能回收，但运行项必须进入可恢复状态，不能继续把照片用于后续页面。恢复必须由用户明确选择：

| 恢复动作 | 结果 |
| --- | --- |
| 重新预览 | 基于剩余素材创建新计划或新计划版本。 |
| 不用这张照片继续 | 生成无该照片的新冻结输入；旧运行项不可继续交付。 |
| 取消本次制作 | 保留审计和已完成结果，不再继续。 |

### 4.4 制作与交付

制作页只显示用户可理解的四阶段：

```text
准备故事 -> 完成文字 -> 绘制画面 -> 等待检查
```

用户可离开并按 `run_id` 恢复。完成后进入 `/storybooks/:storybookId/review` 的“修改与交付”，而不是直接只进入普通详情页：

- 直接创作优先展示对象、照片道具在封面和哪些页出现。
- 派生定制优先展示本次更新、保持原样和原书对照。
- 页面支持满意、改文字、换一张画面；满意状态可恢复但不作为导出门槛。
- 有系统证据缺失时，导出按钮改为“先处理 N 个问题”，定位对应页。
- 证据记录的是本次生成实际读取了哪些冻结输入、素材引用、视觉参考和页级计划；系统不能用模型主观描述替代证据，也不能承诺自动判断“像不像”。视觉像不像由交付页人工检查和必要重绘处理。

## 5. 前端实施说明

### 5.1 页面与组件

| 当前模块 | 改造目标 |
| --- | --- |
| `PersonalizedStorybookPage` | 改为统一容器，根据 `entryType` 渲染想法或来源书摘要；保留现有 3 方向和 6 页能力。 |
| `CustomizeStorybookPage` | 移除独立向导语义，转为统一容器的已有绘本起点适配层；历史路由只负责传递来源书 ID。 |
| `NewStorybookPage` | 保持普通绘本创建，不混入专属定制状态。 |
| `StorybookDetailPage` | 定制按钮跳转统一入口；定制产物默认跳转 review 子视图，普通详情只负责阅读和历史查看。 |
| `DashboardPage` | 将“创建专属故事”改为“创建专属绘本”，定制入口统一跳转。 |

新增或复用组件：

- `PersonalizedEntryPicker`：两种起点，仅专属创作页显示。
- `ObjectAndMaterialsForm`：对象、文字素材、照片入口和草稿恢复。
- `PhotoMaterialSheet`：上传、逐张进度、自然语言用途确认、逻辑删除。
- `StoryDirectionPicker`：直接创作专用，固定 3 个方向。
- `ChangePreview`：派生定制专用，保持/变化/重绘页和可选保持页。
- `VisualReferenceInline`：人物、道具、场景照片存在时嵌入同画风参考确认，不增加向导步骤。
- `CreationProgress`：共享四阶段、离开恢复、失败/取消状态。
- `PersonalizedReview`：共享交付入口、证据摘要与页级操作。

### 5.2 前端状态规则

1. 服务端的 `session`、`plan`、`run`、`asset_reference`、`visual_reference`、`evidence` 是业务真相；本地状态仅保存未提交输入和视图展开状态。原始 `asset` 只表示上传文件，不作为创作计划、删除、恢复和证据的直接业务对象。
2. 所有创建/确认/重试请求使用同一幂等键直至收到结果；按钮在 pending 期间不可重复提交。
3. `plan_stale`、`source_revision_conflict`、`material_unplaced` 或 `asset_revoked` 到达时，停止当前操作，更新可读提示，不能继续使用前端旧计划。
4. 直接创作的方向卡和派生定制的变化页不可由前端静态拼装，必须渲染服务端计划。
5. 移动端最多显示首屏必需内容；上传、视觉参考候选、原书对照和高级页级操作按需展开。

## 6. 后端实施说明

### 6.1 统一领域对象

后端以一个领域模型支撑两种起点：

```text
creation session / source storybook snapshot
-> customization plan + plan items
-> confirmed asset references + visual references
-> customization run + run items
-> output storybooks + personalization evidence
```

- `entry_type=direct_create`：以创建会话和大纲快照为输入，固定 `mode=single`。
- `entry_type=from_storybook`：以源绘本 revision snapshot 为输入，可为 `single` 或 `batch`。
- 一个运行项只为一个对象生成一本输出绘本；源绘本永远只读。
- 所有文字、照片用途、视觉参考、页级偏好和主素材在 run 创建时冻结为 generation input snapshot。

### 6.2 后端接口分组

| API 组 | 前端用途 | 详细契约 |
| --- | --- | --- |
| 创建会话与候选识别 | 直接创作草稿、方向 | 24 号文档 2.2。 |
| 来源书/批量对象 | 选择可定制书、对象预检 | 24 号文档 2.1、2.4。 |
| 资产上传与用途确认 | 照片、预览、撤销 | 24 号文档 2.5、28 号文档。 |
| 定制计划 | 方向、6 页走向、变化页、局部重算 | 24 号文档 2.3。 |
| 视觉参考 | 人物、道具、场景同画风参考确认 | 24 号文档 2.6。 |
| 定制运行 | 制作、进度、取消、单项重试 | 24 号文档 2.7。 |
| 页面与交付 | 改文字、重绘、满意、证据、导出 | 24 号文档 2.8。 |

### 6.3 必须执行的后端守卫

- 源绘本版本、会话大纲、计划版本或资产版本变更后，旧计划不得运行。
- 人物、道具或场景照片选择为“使用”后，未生成并确认同画风视觉参考时，不能进入绘图。
- 锁定文字/照片素材没有明确故事落点时，直接创作不能进入制作。
- 计划返回 `unplaced_assets` 时，不能创建运行；必须重新预览、撤销素材引用或改为不用该照片。
- 派生定制若文字变化影响可见元素，该页必须重绘；用户只能对可选页提出保留偏好。
- 批量对象没有已确认主素材且未明确 `name_only` 时，不能创建运行项。
- 用户撤销照片后，未开始和后续任务不得使用该照片；不能以“运行中”为由拒绝逻辑撤销。
- 同一计划版本只能有一个活跃运行；重复点击返回同一运行。

## 7. 实施顺序

### 阶段 0：契约与兼容地基

1. 先完成 23 至 28 号文档中的数据表、API、状态机、队列和上传契约修订。
2. 后端以兼容方式发布新表、新状态和只读接口，旧页面仍可正常读取。
3. 前端增加 feature flag 和兼容路由，不在真实后端缺失时上线新主流程。

### 阶段 1：统一入口与兼容迁移

1. 修改前端文案和仪表盘入口为“创建专属绘本”。
2. 为统一页面增加 `entryType` 和 `sourceStorybookId`，保留现有直接创作和普通绘本页面。
3. 旧 `/customize` 路由转换为统一入口的兼容适配，不删除历史链接。

### 阶段 2：计划与来源书定制

1. 后端完成 plan/run/版本快照基础实体与 API。
2. 前端用真实计划替换当前静态或同步派生预览。
3. 落地派生书变化页、可选页保持重算、来源更新恢复。

### 阶段 3：真实素材与视觉一致性

1. 接入上传、扫描、用途确认、逻辑撤销。
2. 接入人物、道具和场景视觉参考准备和确认。
3. 将 confirmed 资产与视觉参考写入文本、封面、插图、重绘的冻结输入。

### 阶段 4：制作、修改与交付

1. 用 run 状态替换页面本地生成状态，接入离开恢复、取消、单项重试。
2. 落地专属内容检查/本次变化、页级文字编辑、重绘和满意状态。
3. 使用 evidence 做导出门禁与缺失页定位。

### 阶段 5：批量定制

1. 落地对象预检、主素材确认和 `name_only`。
2. 父运行/子运行项、部分成功、失败项重试和结果列表。
3. 批量仅在源绘本入口开放，最多 30 人。

## 8. 前后端联调地图

| 用户动作 | 前端状态 | API | 后端写入/任务 | 可验证结果 |
| --- | --- | --- | --- | --- |
| 写一句想法 | 草稿保存、候选标签 | session PATCH / candidates | 会话与候选任务 | 刷新仍能恢复想法。 |
| 上传照片并确认用途 | uploading -> awaiting confirmation | asset upload/complete/reference | 资产、分析、视觉参考任务 | 未确认视觉参考或无落点不能开始制作。 |
| 选故事方向 | direction ready -> outlining | select direction | 选中方向、大纲任务、快照 | 返回 6 页大纲。 |
| 选来源书定制 | change preview | create plan | 源版本快照、计划 | 显示保持/变化/重绘页。 |
| 选可选页保持 | recalculating | page preference PATCH | 局部计划重算任务 | 更新页数、重绘数与原因。 |
| 批量确认主素材 | item ready | recipient input PATCH | 对象预检、主素材确认 | 未确认对象不能入队。 |
| 开始制作 | queued/running | create run | run、items、子任务 | 刷新按 run ID 恢复。 |
| 删除照片 | asset reference revoked | `DELETE /storybook-asset-references/{asset_reference_id}` | 撤销本次创作引用、取消后续任务 | UI 显示重新预览/不用照片继续/取消，未选择前不能继续交付。 |
| 改文字/满意 | page update/review | text PATCH / review PUT | 页版本、检查/重绘任务 | 文字和检查状态可恢复。 |
| 导出 | ready / blocked | export PDF | evidence gate | 缺失时定位问题页。 |

## 9. 验收标准

- [ ] 用户在专属绘本入口能明确选择从想法开始或基于已有绘本，不需要理解“专属故事/私人定制”的技术差异。
- [ ] 两条路径均使用对象与素材、故事预览、制作、修改与交付四步骨架。
- [ ] 直接创作只生成 3 个方向，选定后才生成 6 页走向。
- [ ] 派生定制不要求重选故事主题，能解释保持、变化、必改和可选保持页。
- [ ] 人物和道具照片只在用户确认用途并形成 `asset_reference_id` 后进入生成，且生成结果在封面和内页保持同画风与一致性。
- [ ] 每张确认照片都有素材引用、同画风视觉参考、计划落点和 generation input 证据；没有落点时不能开始制作。
- [ ] 删除照片立即停止其后续使用，不影响已导出文件；活跃运行必须让用户显式选择恢复动作。
- [ ] 没有照片时仍可完成完整专属绘本创作。
- [ ] 制作进度、失败、取消、离开恢复和重试均以服务端 run 为准。
- [ ] 批量只在来源绘本入口出现，且每位对象独立确认主素材或 name_only；结果页能展示成功、失败、需补素材和已排除对象，成功对象可独立进入 review，失败对象不阻塞已成功对象交付。
- [ ] 修改与交付页能看到实际素材落点；系统证据缺失时不允许导出。
- [ ] 连续点击创建计划、选择方向、开始制作、重绘或导出，不会产生重复计划、重复运行、重复绘本或重复页级任务。
