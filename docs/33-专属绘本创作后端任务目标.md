# 专属绘本创作后端任务目标

> 依据文档：`docs/29-专属绘本创作统一实施说明.md`、`docs/30-专属绘本创作UI执行方案.md`、`docs/31-专属绘本创作后端落地执行方案.md`、`docs/32-专属绘本创作后端执行目标.md`。  
> 用途：作为新开后端落地任务的目标说明，可直接复制给后端工程师或 Codex 后端任务。  
> 核心原则：后端成为专属绘本创作的业务真相；前端只负责交互呈现，不能靠本地状态兜底。

## 0. 使用方式

这份文档不是产品方案，也不是接口全集，而是**后端执行目标**。开启后端任务时，优先复制第 1 节的启动语；执行过程中用第 2 到第 9 节检查有没有偏离；交付时按第 11 节输出结果。

后端任务必须遵守三条边界：

1. 以 `docs/29-专属绘本创作统一实施说明.md` 为最高产品基线。
2. 以 `docs/31-专属绘本创作后端落地执行方案.md` 为后端落地依据。
3. 本目标只推进当前后端阶段，不能顺手扩展批量、来源书完整 run item、review/evidence 完整交付或公共素材库。

## 1. 可直接复制的目标启动语

```text
请以后端工程师视角，根据以下文档落地“专属绘本创作”的后端能力：

- docs/29-专属绘本创作统一实施说明.md
- docs/30-专属绘本创作UI执行方案.md
- docs/31-专属绘本创作后端落地执行方案.md
- docs/32-专属绘本创作后端执行目标.md

本任务优先完成 Phase 1：照片资产引用与同画风视觉参考闭环。

目标：
1. 不重写现有 storybook_creation_sessions 主流程，只在现有直接创作链路旁补齐真实照片、资产引用、视觉参考、刷新恢复和最终生成门禁。
2. 真实照片上传后，后端必须创建 asset 和 asset_reference；asset 代表原始文件，asset_reference 代表本次创作里的业务引用。
3. 用户填写参考图名称和用途后，后端必须创建或关联 CreationMaterial，并让方向和大纲失效，避免旧计划继续使用错误素材。
4. 选择“使用”的照片必须生成同画风 visual_reference；只有用户确认后的 visual_reference 才能进入最终绘本制作输入。
5. directions:generate 和 outline:generate 对未确认视觉参考只返回 meta.warnings，不阻断故事预览。
6. storybook:generate 必须强阻断 awaiting_usage、awaiting_reference、awaiting_confirmation、failed 状态的资产引用。
7. locked material 如果没有出现在 outline 的任意页面中，storybook:generate 必须返回 material_unplaced，要求重新预览、撤销素材或改为不用。
8. 最终 generation input snapshot 必须冻结 confirmed asset_references、visual_references、material_id、confirmed_at、visibility_scope 和 retention_policy。
9. 页面刷新后，前端必须能通过 session 恢复 asset、asset_reference、visual_reference 的完整状态。
10. 补齐 migration、models、repository、application、controller、generation writeback、测试和 smoke 验证。

边界：
- 不做批量定制。
- 不做来源书变化计划。
- 不做 review/evidence 完整交付页。
- 不做公共素材库沉淀。
- 不做人脸身份识别、相似度承诺或 prompt 参数编辑。

交付前必须运行：
- cargo fmt --all --check
- cargo check
- cargo test
- scripts/smoke-storybook-creation-assets.sh
- scripts/smoke-storybook-creation-ui.sh

交付说明必须列出：新增接口、数据表、状态机、门禁规则、input snapshot 字段、已覆盖测试和仍未做的后续阶段。
```

## 1.1 更短的任务标题

如果只需要给任务命名，使用：

```text
后端落地：专属绘本创作照片资产引用与同画风视觉参考闭环
```

## 1.2 不允许漂移的验收口径

后端实现完成后，产品和前端只看这四件事是否成立：

- 刷新页面后，照片、用途、参考图、确认状态都能从服务端恢复。
- 未确认或失败的照片参考不能进入最终 `storybook:generate`。
- 已确认的 `asset_reference` / `visual_reference` 会被冻结进最终生成输入。
- 无照片的原有专属绘本直接创作主流程不回归。

## 2. 后端成功定义

Phase 1 完成后，系统必须能稳定跑通以下闭环：

```text
创建专属绘本 session
-> 上传真实照片
-> 创建 asset 与 asset_reference
-> 填写显示名称和用途
-> 创建或复用 CreationMaterial
-> 生成同画风 visual_reference
-> 用户确认 visual_reference
-> 生成方向和 6 页大纲
-> 检查素材是否有页级落点
-> storybook:generate 成功入队
-> 刷新页面后恢复上述所有状态
```

完成标准不是“接口能返回”，而是以下事实成立：

- 后端保存照片素材状态。
- 后端鉴权原图和参考图预览。
- 后端维护 `asset_reference.status` 聚合状态。
- 后端决定哪些素材能进入生成输入。
- 后端阻断未确认、失败或没有落点的素材。
- 后端可追溯最终生成实际读取了哪些素材和视觉参考。

## 3. 构建假设

- 现有直接创作主干已经可用，包括创建会话、恢复会话、生成方向、生成大纲和 `storybook:generate` 入队。
- `session` 是创作草稿真相；照片、用途、视觉参考和门禁状态必须跟随 session 恢复。
- `asset` 只表示上传文件，不直接参与故事计划、撤销、恢复和证据。
- `asset_reference` 才是本次创作中的业务引用。
- 原始照片默认只属于本次创作，不进入公共素材库、空间素材库或模板素材。
- 删除照片在 Phase 1 中表示撤销本次引用，不要求物理删除原始文件。
- 所有读写都必须同时校验 `workspace_id`、`creation_session_id` 和 actor 权限。

## 4. 依赖链

```text
Schema / migration
-> Rust models / DTO
-> repository 状态聚合
-> session 响应扩展
-> 上传与预览鉴权 API
-> 用途更新、撤销与 CreationMaterial 关联
-> visual_reference generation job
-> directions / outline 软门禁
-> storybook:generate 强门禁
-> generation input snapshot 冻结
-> API、repository、application、smoke 验证
```

实现时先稳定数据模型和状态机，再接接口和生成门禁；不要把来源书、批量和 review 证据混入第一阶段。

## 5. Phase 1 必做范围

### 5.1 数据与模型

必须新增或补齐：

- `storybook_assets`
- `storybook_asset_references`
- `storybook_visual_references`
- `StorybookCreationSession.asset_references[]`
- 嵌套 `asset`
- 嵌套 `visual_reference`

关键字段必须覆盖：

- `workspace_id`
- `creation_session_id`
- `uploaded_by`
- `storage_key`
- `content_type`
- `byte_size`
- `width`
- `height`
- `visibility_scope=creation_session`
- `retention_policy=session_scoped`
- `asset_reference.kind`
- `asset_reference.usage`
- `asset_reference.display_name`
- `asset_reference.status`
- `asset_reference.material_id`
- `visual_reference.status`
- `visual_reference.generation_job_id`
- `visual_reference.image_storage_key`
- `visual_reference.confirmed_at`
- `visual_reference.confirmed_by`

### 5.2 接口

必须实现：

```http
GET /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-upload-policy
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/assets
PATCH /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
DELETE /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}/visual-reference:generate
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/visual-references/{visual_reference_id}/confirm
GET /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/assets/{asset_id}/preview
```

接口必须具备：

- 幂等键保护。
- 文件类型、大小和数量校验。
- 第 6 张有效照片阻断。
- 原图和参考图预览鉴权。
- `unused` / `revoked` 不进入生成输入。
- 资产变更后使方向和大纲失效。

### 5.3 状态机

后端必须统一维护 `asset_reference.status`：

| 状态 | 含义 |
| --- | --- |
| `awaiting_usage` | 已上传但未选择用途。 |
| `unused` | 用户明确本次不使用。 |
| `revoked` | 本次创作引用已撤销。 |
| `awaiting_reference` | 已选择使用，但没有可确认的视觉参考。 |
| `awaiting_confirmation` | 视觉参考已生成，等待用户确认。 |
| `ready` | 视觉参考已确认，可进入最终生成。 |
| `failed` | 视觉参考生成失败，可重试或改为不用。 |

约束：

- 同一 `asset_reference_id` 同时最多只能有一个 active visual reference。
- 重新生成视觉参考时，旧的待确认或生成中参考必须转为非 active 或 `rejected`。
- 最终门禁读取服务端聚合状态，前端不能自行推断。

## 6. 生成门禁

### 6.1 软门禁

`directions:generate` 和 `outline:generate` 可继续返回结果，但如果存在未处理照片，必须在 `meta.warnings` 返回：

- `code=visual_reference_pending`
- 待处理 `asset_reference_ids`
- `next_action=confirm_visual_reference`
- 面向用户的可读提示

### 6.2 强门禁

`storybook:generate` 必须阻断：

- `awaiting_usage`
- `awaiting_reference`
- `awaiting_confirmation`
- `failed`

`storybook:generate` 不阻断：

- `ready`
- `unused`
- `revoked`

如果锁定素材没有出现在大纲任意页面中，必须返回：

- `code=material_unplaced`
- `unplaced_material_ids`
- `unplaced_material_labels`
- `next_action=regenerate_outline`

## 7. 最小垂直切片

第一条必须跑通：

```text
创建 session
-> 上传 1 张人物照片
-> 命名为“爸爸”
-> 标记为主角
-> 创建 visual reference job
-> visual reference 生成完成
-> 用户确认 visual reference
-> 生成 3 个方向
-> 生成 6 页大纲
-> storybook:generate 成功入队
```

第二条必须阻断：

```text
创建 session
-> 上传 1 张人物照片
-> 标记为主角但不确认 visual reference
-> 调用 storybook:generate
-> 返回 visual_reference_required
```

第三条必须阻断：

```text
创建 session
-> 锁定“爸爸”“小汽车”等素材
-> 生成大纲但其中一个锁定素材没有页级落点
-> 调用 storybook:generate
-> 返回 material_unplaced
```

## 8. 分阶段执行

### Phase 0：契约审计

- 对照前端页面需要的 session 字段。
- 确认现有 generation job 是否能复用视觉参考任务。
- 确认上传文件的本地存储或对象存储策略。
- 确认 `Envelope.meta.warnings` 兼容现有响应。

### Phase 1：Schema、模型与 Repository

- 新增三张表 migration。
- 新增 Rust models / DTO。
- 新增资产 repository。
- 实现创建、查询、更新、撤销、确认和状态聚合。
- 补状态映射和唯一 active visual reference 测试。

### Phase 2：上传、预览与恢复 API

- 实现上传策略接口。
- 实现 multipart 上传。
- 校验文件类型、大小和 5 张上限。
- 返回鉴权预览 URL。
- 扩展 session 恢复响应。

### Phase 3：用途、素材关联与失效

- 支持 `display_name` 和 `usage`。
- 创建或复用 `CreationMaterial`。
- 将 `asset_reference.material_id` 指向素材。
- 素材改名、改用途、撤销、不使用时失效方向和大纲。

### Phase 4：视觉参考任务

- 新增或复用 `storybook_visual_reference` job。
- 任务成功写回 `image_storage_key` 和 `awaiting_confirmation`。
- 任务失败写回 `failed` 和失败原因。
- 用户确认后写回 `confirmed`，并使资产引用进入 `ready`。

### Phase 5：门禁与快照

- directions/outline 接入软门禁 warnings。
- storybook:generate 接入视觉参考强门禁。
- storybook:generate 接入 `material_unplaced` 强门禁。
- 最终 generation input snapshot 冻结 confirmed references。

### Phase 6：验证与回归

- 补 repository、application、controller 测试。
- 补权限、幂等、上传限制、刷新恢复测试。
- 补 smoke 脚本。
- 确认无照片的直接创作主干不回归。

## 9. 验收清单

- [ ] 上传照片后刷新页面不丢失。
- [ ] 每个 creation session 最多 5 张有效照片。
- [ ] 第 6 张有效照片返回稳定错误码。
- [ ] 非图片、超大文件被后端阻断。
- [ ] 原图和参考图预览 URL 必须鉴权。
- [ ] 只有 session 创建者和 `SchoolAdmin` 可操作创作资产。
- [ ] 照片用途、显示名、业务状态由服务端返回。
- [ ] `asset_reference.status` 由服务端聚合。
- [ ] 视觉参考失败可重试或改为不用。
- [ ] 未确认视觉参考可以生成方向和大纲，但返回 warnings。
- [ ] 未确认视觉参考不能调用 `storybook:generate` 成功入队。
- [ ] 锁定素材没有大纲落点时不能调用 `storybook:generate` 成功入队。
- [ ] `unused` / `revoked` 不进入 generation input。
- [ ] 资产引用变化会让方向和大纲失效。
- [ ] 最终 generation input snapshot 包含 confirmed asset references 和 visual references。
- [ ] 重复提交相同幂等键不会产生重复引用、参考图或绘本生成任务。
- [ ] `cargo fmt`、`cargo check`、`cargo test`、asset smoke、UI smoke 通过。

## 10. 不在本目标内

- 批量定制。
- 来源书变化计划。
- run item 编排。
- review/evidence 完整交付页。
- PDF evidence 门禁。
- 公共素材库沉淀。
- 复杂图片安全扫描平台化。
- 图像 prompt 深度优化。
- 人脸身份识别或相似度判断。

这些属于照片资产闭环稳定后的下一阶段，不要混入当前目标。
