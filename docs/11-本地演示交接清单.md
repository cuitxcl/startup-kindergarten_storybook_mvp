# Kindleaf 本地演示交接清单

## 1. 当前交接结论

截至 2026-07-24，Kindleaf 已达到“本地真实 API + PostgreSQL 可演示闭环”标准，整体完成度约 95%。当前可以演示老师登录、空间切换、普通绘本生成、儿童档案维护、单儿童定制绘本、批量定制绘本、PDF 导出、分享链接、园所投稿、市场复制、用户/空间存储限额和基础运营查看。

这个结论不等同于生产上线。真实 Seedream 图片生成、对象存储、邮件短信、完整内容安全审核、部署监控和商业化支付仍属于后续生产化范围。

2026-07-24 最新演示门禁已通过：`CHECK_SMART_RUN_FULL=true ./scripts/check-smart.sh auto` 最终输出 `== ui smoke ok ==`、`== full smoke ok ==` 和 `== smart check ok ==`，覆盖完整 API smoke 与浏览器 UI smoke；快速阶段后端测试为 133 个，API smoke 已确认登录用户个人额度 200MB、个人空间 200MB、园所空间 5GB，并验证园所空间导出会同步计入发起人的个人容量，同时覆盖 `custom_batch=2/...`；UI smoke 已确认运营端 storage 面板可见用户个人限额、个人空间限额、园所空间限额和容量预警线，并覆盖普通绘本详情页生成角色参考图、写回角色、通过登录态 Blob 加载参考图后再继续分页插图流程，以及批量选择 2 个儿童派生独立定制副本。

最新临时库 API smoke 已额外确认 `role_reference_image_png=ok`：角色参考图任务完成后会写回角色，并通过登录态 `/api/workspaces/{workspace_id}/generation-jobs/{job_id}/image` 下载 PNG，不再依赖公共图片直链。

## 2. 一键验收优先级

演示前优先运行：

```sh
./scripts/smoke-api-temp-db.sh
npm --prefix frontend run build
cargo fmt --manifest-path server/Cargo.toml -- --check
cargo test --manifest-path server/Cargo.toml
```

更完整的演示交接门禁：

```sh
CHECK_SMART_RUN_FULL=true ./scripts/check-smart.sh auto
```

这条门禁会固定跑 fast check、完整 API smoke 和浏览器 UI smoke；UI smoke 启动 Chrome 时如果默认调试端口不可用，会自动尝试备用端口。

如果只想快速确认当前改动没有打坏主线：

```sh
./scripts/check-fast.sh
```

## 3. 本地启动

启动 PostgreSQL：

```sh
docker compose up -d postgres
```

初始化数据库：

```sh
cd server
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
  cargo run -p migration -- up

DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
  cargo run --features db -- db seed
```

启动后端：

```sh
cd server
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/kindleaf_development \
KINDLEAF_DEMO_SEED=1 \
KINDLEAF_GENERATION_PROVIDER=mock \
KINDLEAF_COST_BUDGET_WARNING_PERCENT=80 \
  cargo run --features db -- start
```

启动前端 API 模式：

```sh
cd frontend
npm run dev:api
```

访问入口：

- `http://127.0.0.1:5173/`
- `http://127.0.0.1:5173/app`
- `http://127.0.0.1:5173/app/school-1/dashboard`

## 5. 推荐演示路线

### 普通绘本主线

1. 登录 `lin@example.com / demo`。
2. 进入星星幼儿园工作台。
3. 点击创建普通绘本。
4. 按“需求 -> 绘本方案 -> 角色道具 -> 分页图文 -> 预览导出”完成向导。
5. 进入绘本详情，查看分页、角色和生成历史。
6. 生成插图。
7. 导出 PDF。
8. 创建分享链接。
9. 打开 `/link/share/{token}`，确认匿名分享页不显示主应用导航。

### 单儿童定制主线

1. 打开儿童档案页。
2. 新增儿童档案，填写称呼、年龄段、兴趣、特质和关注点。
3. 回到普通绘本详情，点击生成定制版。
4. 选择孩子，确认档案，选择定制强度。
5. 生成定制方案。
6. 生成独立定制副本。
7. 打开定制绘本详情，继续编辑、导出或分享。

### 批量定制主线

1. 准备一本已完成的普通绘本作为母本。
2. 打开绘本详情，点击生成定制版。
3. 在定制绘本向导中切换到批量生成。
4. 选择 2 个或多个儿童。
5. 确认档案、定制强度和定制方案。
6. 点击生成定制副本。
7. 系统会为每个儿童创建独立定制绘本副本，并跳转到第一本结果。

### 园所沉淀与市场复用

1. 进入园所绘本列表，选择一个普通绘本。
2. 在园所管理的投稿流程中完成隐私确认。
3. 进入平台运营审核，上架为市场模板。
4. 回到绘本市场，复制模板到当前空间。
5. 打开复制出来的新绘本详情，确认它可以继续编辑和定制。

## 6. 当前剩余缺口

- 真实图片生成仍需要配置 `SEEDREAM_API_KEY` 或 `ARK_API_KEY` 后运行真实 Seedream smoke。2026-07-24 最新 readiness 已确认：DeepSeek key、本地 PostgreSQL、端口、Seedream endpoint/model、storage 写入和文件名规则都正常，当前只缺图片模型 key。
- 真实 DeepSeek 文本已具备接入和 smoke，但 prompt 质量仍需产品验收。
- PDF 是本地基础排版，尚未做专业绘本排版。
- 文件存储仍是本地 storage service，生产环境应换对象存储或持久化目录。
- 邀请链接通过页面展示和复制，尚未接邮件或短信。
- 隐私和内容安全已有基础拦截，尚未达到完整人工审核和图片审核标准。

## 7. Seedream Key 到手后的最短验收

不消耗额度的前置检查：

```sh
SEEDREAM_API_KEY=真实-key ./scripts/check-real-provider-readiness.sh --seedream
```

真实单页插图验收，会调用 Seedream 并可能消耗额度：

```sh
SEEDREAM_API_KEY=真实-key ./scripts/smoke-real-seedream-image.sh
```

成功时应看到这些关键输出：

- `real_seedream_provider=seedream/...`
- `real_seedream_image_job=...`
- `real_seedream_image=.../.tmp/real-seedream-image.png`
- `real_seedream_cost=.../CNY`
- `== real Seedream image smoke ok ==`

失败时优先查看：

- `.tmp/smoke-real-seedream-image/server.log`
- `.tmp/smoke-real-seedream-image/migrate.log`
- 终端里的 provider readiness 输出，尤其是 key、endpoint、model 和 storage 检查项。

如果使用火山方舟统一 key，也可以改用：

```sh
ARK_API_KEY=真实-key ./scripts/check-real-provider-readiness.sh --seedream
ARK_API_KEY=真实-key ./scripts/smoke-real-seedream-image.sh
```

DeepSeek + Seedream 组合验收：

```sh
DEEPSEEK_API_KEY=真实-deepseek-key SEEDREAM_API_KEY=真实-seedream-key ./scripts/smoke-real-composite-provider.sh
```
