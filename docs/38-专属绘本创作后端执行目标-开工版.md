# 专属绘本创作后端执行目标（开工版）

> 依据：`docs/29-专属绘本创作统一实施说明.md`、`docs/30-专属绘本创作UI执行方案.md`、`docs/31-专属绘本创作后端落地执行方案.md`、`docs/37-专属绘本创作后端执行目标-任务版.md`。  
> 用途：开启后端落地任务时直接引用，作为后端工程师或 Codex 后端任务的执行目标。  
> 核心口径：后端必须成为“专属绘本创作”的业务真相；前端只负责输入、展示和触发动作，不能用本地状态兜底刷新恢复、制作门禁、证据展示或导出判断。

## 0. 可直接复制的后端目标

```text
请以后端工程师视角，根据以下文档落地“专属绘本创作”后端闭环：

- docs/29-专属绘本创作统一实施说明.md
- docs/30-专属绘本创作UI执行方案.md
- docs/31-专属绘本创作后端落地执行方案.md
- docs/37-专属绘本创作后端执行目标-任务版.md

本任务不是重写已有绘本生成主干，而是在现有 storybook_creation_sessions、generation_jobs、storybooks、导出/分享能力上补齐后端真实状态：

1. 照片上传、资产引用、用途命名、逻辑撤销和刷新恢复。
2. 同画风 visual_reference 生成、确认、失败重试和最终生成门禁。
3. 直接创作 generation input snapshot，冻结方向、大纲、素材引用、视觉参考和页级证据。
4. 基于已有绘本的 source_snapshot、customization_plan 和 page_plan。
5. 单人/批量 customization_run、run_item、失败恢复、重试和放弃。
6. review evidence、页级证据、导出/分享/公开导出前的 evidence gate。

交付时必须给出：新增或修改的数据表、接口、状态机、门禁规则、generation input snapshot 字段、权限与隐私策略、已运行验证、未完成项和风险。
```

## 1. Build Assumptions

- 现有直接创作主干可复用，包括创建 session、恢复 session、生成方向、生成大纲和开始生成。
- 本轮优先补齐后端业务闭环，不做绘本生成主链路大重构。
- `asset` 只表示原始上传文件；`asset_reference` 才表示照片在本次创作里的业务引用。
- 所有选择“使用”的人物、道具、宠物、场景照片，必须先生成并确认同画风 `visual_reference`，才能进入最终制作。
- 来源绘本永远只读；专属版本必须生成独立输出绘本。
- 所有会影响最终生成的输入，都必须在 generation job、run 或 run item 创建时冻结到 snapshot。

## 2. Dependency Chain

```text
产品边界与现有代码审计
-> Schema / migration
-> Rust models / DTO
-> Repository 聚合查询与状态计算
-> Application 状态机、权限、门禁、幂等、快照
-> Controller / API
-> Generation input snapshot / job 写回
-> Session / review 查询响应
-> Export / share evidence gate
-> cargo / API smoke / UI smoke 验证
```

实现顺序要求：

- 先稳定数据库、状态机和响应结构，再接前端真实 API。
- 先跑通直接创作单本垂直闭环，再扩展来源书、批量和 review evidence。
- 门禁和 snapshot 必须早于导出/分享接入，避免产物无法追溯。

## 3. Phase 1：照片资产与视觉参考闭环

目标：把 UI 中“上传照片 -> 命名 -> 选择用途 -> 生成同画风参考 -> 确认参考 -> 刷新恢复 -> 开始制作门禁”全部落到后端。

必须完成：

- 新增或补齐 `storybook_assets`、`storybook_asset_references`、`storybook_visual_references`。
- 提供上传策略、multipart 上传、预览鉴权、用途更新、撤销引用、视觉参考生成、视觉参考确认接口。
- session 恢复响应返回 `asset_references[]`，包含 `asset` 摘要和 `visual_reference` 状态。
- 后端统一计算 `asset_reference.status`，至少覆盖 `awaiting_usage`、`awaiting_reference`、`awaiting_confirmation`、`ready`、`unused`、`revoked`、`failed`。
- `directions:generate` 和 `outline:generate` 可以对未完成照片返回 `meta.warnings`，但允许用户先看故事预览。
- `storybook:generate` 必须强阻断未确认、失败、撤销后仍被使用、没有故事落点的照片。
- 直接创作 generation input snapshot 冻结 `asset_reference_id`、`asset_id`、`display_name`、`usage`、`material_id`、`visual_reference_id`、`confirmed_at`、`outline` 和 `selected_direction`。

完成信号：

- 上传照片后刷新页面不丢失。
- 每个 session 最多 5 张有效照片。
- 非图片、超大文件、第 6 张照片、越权预览都有稳定错误码。
- `unused` / `revoked` 不进入新的生成输入。
- 无照片的直接创作原流程不回归。

## 4. Phase 2：来源书计划与版本快照

目标：让“基于已有绘本创作专属版本”由后端保存真实计划，不能依赖前端静态拼装。

必须完成：

- 持久化 `customization_plan`。
- 冻结 `source_snapshot`：来源书 id、标题、状态、更新时间、页数、页 id、页面摘要和可定制性判断。
- 生成 `page_plan`：保持原样、对象版本、必须重绘、可选重绘、尽量保持和重绘原因。
- 单人定制冻结 `target_child_id`、`target_child_nickname`、`primary_material` 或 `name_only`。
- 来源绘本更新后，旧计划运行返回 `source_revision_conflict`，并给出 `next_action=refresh_source_plan`。
- 输出绘本能反查来源书、计划摘要、目标对象和主素材。

完成信号：

- review 页刷新后仍能展示来源书、目标对象和变化计划。
- 来源绘本更新后不能继续使用旧计划制作。
- 新增素材只影响被定制对象、被选变化页和服务端判定必须重绘的关键页。

## 5. Phase 3：Run、Run Item 与批量恢复

目标：把制作进度、失败、取消、重试、离开恢复从前端本地状态转移到后端。

必须完成：

- 新增或补齐 `customization_runs` 和 `customization_run_items`。
- 同一计划版本只能有一个 active run，重复点击开始制作返回同一 run。
- 单人 run 只有一个 item；批量 run 每个对象一个 item。
- 每个 item 独立冻结对象快照、主素材选择、状态、错误和输出绘本。
- item 状态至少覆盖 `queued`、`running`、`succeeded`、`failed`、`canceled`、`retrying`。
- 批量部分失败不回滚成功项；失败项可单项重试或放弃。
- 用户撤销照片后，未开始和后续任务不得继续使用该照片；旧计划必须返回 `asset_revoked` 或要求重新预览。

完成信号：

- 连续点击开始制作不会产生重复任务或重复绘本。
- 批量成功项可进入 review，失败项不阻塞成功项交付。
- 每个批量输出绘本都有自己的对象快照和主素材证据。
- 运行中取消、失败、重试、放弃后，前端能按后端状态恢复。

## 6. Phase 4：Review Evidence 与交付门禁

目标：让修改与交付页能解释“这本书用了什么素材、哪些页变化、为什么变化、证据是否完整”，并由后端决定能否导出。

必须完成：

- 产物详情返回定制计划摘要、run、run item、冻结输入和页级 evidence。
- 页级 evidence 覆盖来源页、目标页、文字变化、素材落点、视觉参考、重绘原因和实际读取的输入。
- 文本修改、页级重绘、满意状态由后端保存。
- 导出、分享、公开导出前检查 evidence 完整性。
- evidence 缺失时返回问题页、缺失字段和修复动作。
- 普通绘本导出不能被专属绘本 evidence gate 误伤。

完成信号：

- review 页面刷新后证据不丢失。
- 用户能看到素材落点、变化原因和原书对照。
- evidence 不完整时导出被阻断，并返回可定位原因。
- 导出成功的绘本可追溯到 run、run item 和 generation input snapshot。

## 7. 不在本轮目标内

- 公共素材库或跨作品照片库。
- 人脸识别、身份识别、相似度评分或“像不像”自动承诺。
- 用户编辑 prompt、模型参数、权重或底层生成策略。
- 商业化付费、额度、账单。
- 隐私删除全链路自动擦除。
- 大规模队列治理平台化。

## 8. Hard Gates

- 前端不得自行推断 3 个方向、6 页走向、素材落点、必须重绘页、预计制作时间或 evidence 完整性。
- 已选择使用的照片没有 confirmed visual reference 时，不能进入最终制作。
- 锁定素材没有明确故事落点时，不能创建最终生成任务或 customization run。
- 来源书版本、计划版本、资产引用或主素材选择变化后，旧计划不得继续运行。
- 批量对象没有确认主素材且未明确 `name_only` 时，不能创建该对象的 run item。
- 同一计划版本重复开始制作必须幂等。
- 证据缺失时，导出/分享/公开导出必须被阻断并返回可定位错误。

## 9. Validation Checkpoints

后端交付前至少运行：

```bash
cargo fmt --all --check
cargo check --features db
cargo test --features db
scripts/smoke-storybook-creation-assets.sh
scripts/smoke-storybook-creation-ui.sh
```

最小 smoke 必须覆盖：

- 创建专属绘本 session。
- 上传 1 张照片并命名。
- 生成并确认 visual reference。
- 刷新恢复 session。
- 未确认 visual reference 时最终生成被阻断。
- 已确认 visual reference 后最终生成成功入队。
- 来源书计划包含 `source_snapshot`。
- 来源书变更后旧计划返回 `source_revision_conflict`。
- 批量定制每个输出绘本冻结自己的对象和主素材。
- review 能读取 run / run item / page evidence。
- evidence 缺失时导出被阻断，普通绘本导出不受影响。

如果某条验证无法运行，交付说明必须写明原因、影响范围和替代验证。

## 10. Main Implementation Risks

- 前端本地状态和后端真相并存，导致刷新后状态不一致。
- 混用 `asset_id` 和 `asset_reference_id`，导致撤销、恢复、门禁和证据链失效。
- 只返回 UI 字段、不冻结 generation input snapshot，导致最终绘本无法追溯。
- 来源书定制缺少 `source_snapshot`，源绘本更新后仍使用过期计划。
- 批量定制共享一份主素材假设，导致对象素材串用。
- run / run item 缺少幂等约束，连续点击产生重复任务和重复绘本。
- evidence 只由前端拼装，导出和审计无法判断实际生成输入。
