# 专属绘本创作 UI 执行方案

> 依据：`29-专属绘本创作统一实施说明.md`。  
> 定位：供 UI/UX、前端、后端联调和测试执行的界面方案。  
> 原则：产品对外只表达“专属绘本创作”，不再让用户理解“专属故事”和“私人定制”的技术差异。

## 1. UI summary

专属绘本创作是一套统一创作工作台，支持两个故事起点：

| 起点 | 用户心智 | UI 重点 |
| --- | --- | --- |
| 从想法开始 | 我有一个想做给某个孩子的故事 | 让用户低门槛表达想法，确认系统理解，选择 3 个故事方向，再确认 6 页走向。 |
| 基于已有绘本 | 我喜欢这本绘本，想做成某个孩子的版本 | 让用户确认来源书、对象和素材，理解哪些页保持、变化或必须重绘，再生成独立副本。 |

统一体验骨架固定为四步：

```text
对象与素材 -> 故事预览 -> 制作 -> 修改与交付
```

UI 的核心任务不是展示 AI 技术，而是让用户持续理解四件事：

- 系统听懂了什么。
- 哪些名字、文字素材和照片会被使用。
- 照片已经转成同画风视觉参考，并落到哪些页。
- 最终产物是否具备可交付证据，缺什么问题需要处理。

## 2. Users and jobs

### 2.1 个人用户或家长

主要任务：

- 用一句想法给孩子做一本专属绘本。
- 上传孩子、玩具、宠物或场景照片，让成品有真实专属感。
- 快速检查故事是否跑偏，并导出可分享的绘本。

关键担心：

- 照片会不会被直接贴到画面里。
- AI 有没有真正用到孩子和物品。
- 不满意时能不能只改局部。

### 2.2 幼儿园老师

主要任务：

- 为课堂、规则引导、家园沟通或某个孩子制作专属绘本。
- 基于已有普通绘本生成一个或多个孩子版本。
- 批量制作时能看到每个孩子的状态，失败项不影响成功项。

关键担心：

- 会不会误改普通母本。
- 批量对象是否都确认了主素材或仅使用称呼。
- 交付前是否存在素材使用和证据缺失。

## 3. Product UI principles

1. 每个屏幕只有一个主动作。
2. 面向用户展示“故事理解、素材落点、制作阶段和交付问题”，不展示 prompt、模型参数、任务 ID 或原始 JSON。
3. 照片 UI 始终表达为“本次创作素材引用”，不是素材库；删除是撤销本次使用，不是删除原文件。
4. 所有不能继续的状态都要给出恢复动作：重新预览、不用这张照片继续、取消本次制作、重试或返回处理。
5. 直接创作和来源书定制共享页面骨架，但预览内容不同，避免把两条路径混成一个大表单。
6. 移动端优先显示当前步骤、主动作和阻断问题；来源书对照、视觉参考详情、批量明细默认折叠。

## 4. Screens or routes

| 路由 | 页面 | UI 行为 |
| --- | --- | --- |
| `/app/:workspaceId/storybooks/personalized/new` | 专属绘本创作统一入口 | 若无 `sourceStorybookId`，先显示起点选择；若带来源书参数，直接进入“基于已有绘本”。 |
| `/app/:workspaceId/storybooks/:storybookId/customize` | 历史兼容入口 | 不渲染独立向导，重定向到统一入口并携带 `sourceStorybookId`。 |
| `/app/:workspaceId/storybooks/:storybookId/review` | 修改与交付 | 专属产物默认进入；可带 `run_item_id` 定位本次输出和证据；支持本次素材落点、页级修改、重绘、满意和导出门禁。 |
| `/app/:workspaceId/storybooks/new` | 创建普通绘本 | 保持现有普通绘本创建语义，不混入专属状态。 |
| `/app/:workspaceId/dashboard` | 工作台 | “创建专属故事”改为“创建专属绘本”，跳转统一入口。 |
| `/app/:workspaceId/storybooks/:storybookId` | 绘本详情 | 普通绘本显示“创作专属版本”；专属产物优先显示“检查与交付”。 |

## 5. Primary flow

### 5.1 进入与起点选择

```text
工作台 / 绘本详情
-> 创建专属绘本
-> 选择起点
-> 进入对象与素材
```

首屏内容：

- 标题：创建专属绘本。
- 两个起点卡片：
  - 从想法开始。
  - 基于已有绘本。
- 若存在未完成草稿，顶部显示恢复条：“发现上次未完成的专属绘本创作”。

主动作：

- 未选择起点时不显示全局“下一步”。
- 起点卡片本身是选择动作，选择后进入对应对象与素材页面。

### 5.2 起点 A：从想法开始

```text
填写一句想法和对象称呼
-> 系统保存草稿并识别候选素材
-> 用户锁定文字素材和确认照片用途
-> 生成 3 个故事方向
-> 选择方向
-> 生成 6 页走向
-> 开始制作
```

对象与素材页主动作：

- 初始为“看看故事怎么讲”。
- 有已确认照片但视觉参考未确认时，主动作变为“先确认视觉参考”。
- 有未落点素材时，主动作禁用，提示“还有素材没有放进故事，请重新预览或撤销素材”。

故事预览页主动作：

- 未选择方向：选择方向卡。
- 已选择方向但无 6 页走向：生成 6 页走向。
- 已有 6 页走向且无阻断：开始制作。

### 5.3 起点 B：基于已有绘本

```text
选择或确认来源绘本
-> 选择单人 / 为多人制作
-> 为每个对象确认主素材或仅使用称呼
-> 确认照片用途和视觉参考
-> 查看真实变化计划
-> 对可选页选择尽量保持
-> 开始制作
```

对象与素材页主动作：

- 单人模式：确认对象与素材。
- 批量模式：确认已选对象。
- 批量中未确认主素材或 `name_only` 的对象以行内阻断显示。

故事预览页主动作：

- 单人模式：确认这些变化。
- 批量模式：确认统一变化并进入批量制作。
- 可选保持页重算中，主动作禁用并显示“正在重新计算重绘范围”。

来源书选择规则：

- 从工作台进入并选择“基于已有绘本”时，先展示可定制普通绘本列表。
- 列表每本书必须显示封面、标题、页数、更新时间和状态原因：可定制、仍在制作、需要先处理问题、不是普通绘本。
- 不可定制项可展示但不可选择，并给出明确修复路径，例如“先完成文字和插图”或“返回详情处理质量问题”。
- 从普通绘本详情或旧 `/customize` 路由进入时，跳过列表，直接展示来源书摘要；若来源书不可定制，则停留在对象与素材页顶部显示阻断说明。

## 6. Layout sections

### 6.1 统一创作容器 `PersonalizedCreationWorkspace`

桌面端布局：

- 顶部：页面标题、来源标识、草稿保存状态、离开提示。
- 左侧：四步流程导航，显示当前步骤、已完成步骤、阻断步骤。
- 中间：当前步骤主内容。
- 右侧：创作摘要栏，展示对象、起点、来源书、已确认素材、阻断问题和预计制作时间。
- 底部：当前步骤主动作条，移动端固定在底部。

移动端布局：

- 顶部保留标题和步骤进度。
- 摘要栏折叠为“本次创作摘要”抽屉。
- 主动作固定底部，阻断提示在按钮上方。
- 上传、视觉参考、原书对照和批量明细默认折叠，只在需要处理时展开。

### 6.2 对象与素材

视觉顺序：

1. 起点说明区。
2. 对象信息区。
3. 故事想法或来源书摘要。
4. 文字素材区。
5. 照片素材区。
6. 视觉参考确认区。
7. 草稿和阻断提示。

直接创作显示：

- 一句话故事想法，多行输入，至少 8 个有效字符。
- 对象称呼，选填但建议填写。
- 系统识别的候选素材，可增删和锁定，最多锁定 3 个文字素材。

来源书定制显示：

- 来源绘本封面、标题、页数、状态和可定制原因。
- 对象选择：单人模式为列表/搜索；批量模式为可勾选列表。
- 不再显示故事想法输入。
- 显示说明：“会保留原书主线、页数和阅读节奏，只改变确认的对象和必要画面。”

照片素材显示：

- 上传入口支持人物、玩具/物品/宠物、场景，本次创作最多 5 张真实照片。
- 已达到 5 张时，上传入口禁用，提示“最多添加 5 张照片；可以先从本次创作移除一张再继续”。
- 每张照片有用途选择：
  - 人物：主角、故事里的朋友、只保留名字、不使用。
  - 玩具/物品/宠物：把它写进故事、不使用。
  - 场景：用作故事场景、不使用。
- 确认使用后显示同画风视觉参考状态：准备中、待确认、已确认、生成失败。
- 删除文案为“从本次创作移除”，确认说明不承诺删除原文件。

### 6.3 故事预览

直接创作分两段：

- 故事方向：固定 3 张方向卡。
- 6 页走向：选定方向后生成，逐页展示文字摘要、画面描述和素材落点。

方向卡内容：

- 方向标题。
- 一句话剧情。
- 适合场景。
- 会使用的素材。
- 专属落点。

6 页走向内容：

- 页码和节奏标签。
- 页面文字摘要。
- 画面描述。
- 已落点素材，包括文字素材和视觉参考。
- 单页补充要求入口。

来源书定制分三段：

- 来源摘要：封面、页数、阅读节奏、本次不会修改母本。
- 变化计划：保持不变、变成对象版本、必须重绘、可选变化页。
- 可选保持：对可选页提供“尽量保持这一页”的开关，触发服务端重算。

变化页卡片内容：

- 原页缩略图或占位。
- 变化类型徽标。
- 变化原因。
- 将使用的对象/素材。
- 可选页操作：尽量保持这一页。

### 6.4 制作

制作页只显示四阶段：

```text
准备故事 -> 完成文字 -> 绘制画面 -> 等待检查
```

页面内容：

- 当前阶段大标题。
- 简短说明。
- 预计剩余时间或队列提示。
- 本次创作摘要。
- 可离开提示：“可以先离开，稍后会按本次制作进度恢复。”
- 失败时显示可重试项和失败原因。

不显示：

- job id。
- provider。
- prompt。
- 模型参数。

### 6.5 修改与交付

直接创作优先展示：

- 对象和确认素材。
- 封面和每页实际使用的素材落点。
- 证据缺失问题。

来源书定制优先展示：

- 本次更新页。
- 保持原样页。
- 原书对照。
- 重绘原因。

页面结构：

1. 交付状态栏：可导出 / 需处理 N 个问题 / 制作未完成 / 有撤销素材待恢复。
2. 绘本预览：封面和分页卡。
3. 页级操作：满意、改文字、换一张画面。
4. 证据摘要：素材引用、视觉参考、冻结输入和页级计划。
5. 导出区：PDF 导出、分享入口。

导出门禁：

- evidence 完整时显示“导出 PDF”。
- evidence 缺失时显示“先处理 N 个问题”，点击定位到第一个问题页。

## 7. Component responsibilities

| 组件 | 职责 |
| --- | --- |
| `PersonalizedCreationWorkspace` | 统一容器，管理 `entryType`、当前步骤、路由参数、草稿恢复和摘要栏。 |
| `PersonalizedEntryPicker` | 起点选择，只在无来源书和无活动会话时显示。 |
| `ObjectAndMaterialsForm` | 对象、想法/来源摘要、文字素材、照片素材入口和草稿保存状态。 |
| `SourceStorybookPicker` | 从统一入口选择来源普通绘本，显示可定制、仍在制作或需要处理的原因。 |
| `SourceStorybookSummary` | 展示来源绘本状态、页数、封面、可定制性和“母本不修改”提示。 |
| `RecipientSelector` | 单人对象选择，支持空态、搜索、预选 `childId`。 |
| `BatchRecipientTable` | 批量对象选择、主素材确认、`name_only`、状态和上限提示。 |
| `TextMaterialChips` | 候选素材、锁定素材、增删和未落点提示。 |
| `PhotoMaterialSheet` | 上传、用途确认、进度、错误、撤销本次引用。 |
| `VisualReferenceInline` | 同画风视觉参考生成状态、候选预览、确认和失败重试。 |
| `StoryDirectionPicker` | 直接创作的 3 个方向选择，显示素材落点。 |
| `DirectOutlinePreview` | 6 页走向、单页补充、素材落点和未覆盖原因。 |
| `ChangePreview` | 来源书变化计划、保持/变化/重绘/可选保持页、预计时间。 |
| `CreationProgress` | run 状态驱动的四阶段进度、离开恢复、取消和失败重试。 |
| `AssetRevocationRecovery` | 撤销照片后的恢复动作：重新预览、不用照片继续、取消本次制作。 |
| `PersonalizedReview` | 修改与交付主页面，管理页级操作、满意状态、证据和导出门禁。 |
| `EvidenceIssueList` | 显示证据缺失和定位页。 |

## 8. User actions

| 用户动作 | UI 即时反馈 | 服务端结果 | 下一步 |
| --- | --- | --- | --- |
| 选择“从想法开始” | 进入对象与素材，显示想法输入 | 创建或恢复 `session` | 填写想法。 |
| 输入故事想法 | 显示草稿保存中/已保存 | PATCH session，候选识别 | 锁定素材或上传照片。 |
| 锁定文字素材 | 素材 chip 高亮 | PATCH materials，旧计划置 stale | 重新生成方向。 |
| 上传照片 | 显示上传进度 | 创建 `asset` | 确认用途。 |
| 上传第 6 张照片 | 上传入口禁用并说明上限 | 不发起请求 | 移除一张照片或继续使用现有素材。 |
| 确认照片用途 | 显示视觉参考准备中 | 创建 `asset_reference_id` 和视觉参考任务 | 确认同画风参考。 |
| 确认视觉参考 | 参考图标记已确认 | 写入 `visual_reference_id` | 进入预览或重新预览。 |
| 生成方向 | 骨架展示 3 张方向卡 | 返回 3 个方向 | 选择方向。 |
| 选择方向 | 卡片选中，主动作变为生成走向 | 保存 selected direction | 生成 6 页走向。 |
| 单页补充要求 | 仅该页显示重算中 | PATCH page instruction | 更新该页文字、画面描述和素材落点。 |
| 选择来源书 | 显示来源摘要 | 创建 source snapshot | 选择对象。 |
| 可选页尽量保持 | 该页显示重算中 | PATCH page preference | 更新重绘范围。 |
| 开始制作 | 进入四阶段进度页 | 创建 run，冻结输入 | 等待完成或离开恢复。 |
| 撤销照片引用 | UI 立即移除引用并显示恢复选择 | DELETE asset reference | 重新预览、不用继续或取消。 |
| 改文字 | 页卡进入编辑态 | PATCH page text | 检查/必要重绘。 |
| 换一张画面 | 页卡显示重绘中 | 创建页级重绘任务 | 返回新图并保留证据。 |
| 标记满意 | 页卡显示满意状态 | PUT review state | 可撤回。 |
| 导出 PDF | 可导出时显示进度 | evidence gate + export job | 下载或显示缺失问题。 |

## 9. State matrix

| 状态 | UI 表现 | 主动作 |
| --- | --- | --- |
| Initial load | 页面骨架，保留步骤导航尺寸 | 不可操作。 |
| Empty no draft | 显示起点选择和一句价值说明 | 选择起点。 |
| Draft found | 顶部恢复条，显示上次起点、对象、更新时间 | 恢复 / 放弃。 |
| Saving draft | 字段旁显示“保存中” | 当前主动作可用但需使用同一幂等键。 |
| Validation error | 字段下方说明如何修正 | 禁用当前步骤主动作。 |
| Uploading | 照片卡显示进度条和取消入口 | 不影响文字素材操作。 |
| Photo limit reached | 上传入口禁用，显示 5 张上限说明 | 移除照片引用后恢复上传。 |
| Awaiting usage confirmation | 照片卡显示用途按钮组 | 先确认用途。 |
| Visual reference pending | 显示参考图骨架和“正在转成绘本画风” | 不能开始制作。 |
| Visual reference failed | 显示失败原因和重试 | 重试 / 不使用。 |
| Plan stale | 顶部阻断 Notice，说明变化来源 | 重新预览。 |
| Material unplaced | 素材摘要中标红未落点项 | 重新预览 / 撤销素材 / 改为不使用。 |
| Source revision conflict | 来源摘要显示新版提示 | 刷新来源书并重新生成计划。 |
| Creating plan | 预览区骨架，主动作 loading | 等待。 |
| Plan ready | 显示方向/走向或变化计划 | 开始制作。 |
| Run queued/running | 四阶段进度，允许离开 | 取消本次制作。 |
| Run failed | 显示失败阶段和可重试项 | 重试 / 取消。 |
| Asset revoked during run | 显示恢复选择，不继续交付 | 重新预览 / 不用继续 / 取消。 |
| Review ready | 显示页级检查和导出区 | 导出 PDF。 |
| Evidence missing | 导出按钮变为问题处理入口 | 先处理 N 个问题。 |
| Permission restricted | 显示无权限说明和返回入口 | 返回绘本列表。 |
| Offline or reconnecting | 顶部弱提示“连接恢复后继续同步” | 本地输入可保留，提交动作禁用。 |

## 10. Data requirements

### 10.1 页面级数据

统一创作容器需要：

- `workspace`：当前空间、角色和权限。
- `entry_type`：`direct_create` 或 `from_storybook`。
- `session`：会话 ID、状态、草稿字段、候选素材、已选方向。
- `source_storybook_snapshot`：来源书 ID、标题、封面、页数、revision、可定制状态。
- `plan`：方向、6 页走向或变化计划、未落点素材、预计时间、版本。
- `asset_references`：本次创作素材引用，不直接以原始 `asset_id` 驱动业务操作。
- `visual_references`：同画风参考状态、预览图、确认状态。
- `run`：制作运行、运行项、四阶段状态、失败和取消状态。
- `evidence`：冻结输入、素材引用、视觉参考和页级计划证据。

### 10.2 组件数据边界

| 组件 | 读取 | 写入 |
| --- | --- | --- |
| `ObjectAndMaterialsForm` | session、source snapshot、materials、asset references | session patch、materials patch、asset usage confirm |
| `SourceStorybookPicker` | storybook list、customizable status、pagination/search query | selected source storybook |
| `PhotoMaterialSheet` | upload policy、asset、asset references、visual references | upload complete、usage confirm、reference revoke |
| `StoryDirectionPicker` | plan directions、materials | selected direction |
| `DirectOutlinePreview` | outline pages、material placements、unplaced assets | page instruction patch |
| `ChangePreview` | source snapshot、plan items、optional pages | page preference patch |
| `CreationProgress` | run、run items、stage summary | cancel run、retry item |
| `PersonalizedReview` | output storybook、pages、evidence、review state | text patch、redraw、satisfied、export |

### 10.3 前端不得自行推断的数据

- 3 个故事方向。
- 6 页走向。
- 素材落点。
- 哪些页必须重绘。
- 预计制作时间。
- evidence 是否完整。
- 来源书是否可定制。

这些必须由服务端返回，前端只负责展示、选择和恢复动作。

## 11. Visual and interaction notes

### 11.1 视觉层级

- 主色用于当前步骤、主动作和选中态。
- 警告色只用于阻断状态：未落点、证据缺失、版本冲突、撤销素材待恢复。
- 成功色用于已确认、已完成、可导出。
- 图片和页面缩略图要保持稳定比例，避免加载后布局跳动。
- 卡片只用于方向、页面、照片和批量对象这些重复项；页面大区块不做卡片嵌套。

### 11.2 文案语气

推荐文案：

- “创建专属绘本”
- “从想法开始”
- “基于已有绘本”
- “对象与素材”
- “看看故事怎么讲”
- “确认同画风参考”
- “这张照片会作为角色参考”
- “这张照片只用于本次创作”
- “尽量保持这一页”
- “先处理 N 个问题”

避免文案：

- “AI 参数”
- “prompt”
- “权重”
- “模型任务”
- “asset_id”
- “run item”

### 11.3 控件规范

- 起点选择用两张大选项卡。
- 单人/批量用 segmented control。
- 照片用途用按钮组或单选列表。
- 可选页保持用开关。
- 页级操作用图标加文字按钮，建议配合 lucide 图标：编辑、刷新、检查、下载。
- 阻断动作使用 Notice，不放在普通 toast 里。
- 成功保存可用轻 toast，不打断用户。

## 12. Accessibility and privacy notes

- 所有步骤导航使用 `aria-current="step"`。
- 上传和视觉参考状态必须有文本状态，不只靠颜色。
- 禁用按钮使用可读的禁用原因，现有 `ActionButton` 的 `disabledHint` 可继续复用。
- 照片撤销前确认文案必须说明：“这会停止本次创作后续使用该照片，已经完成的外部绘制不能回收。”
- 交付页不承诺系统自动判断“像不像”；文案应表达为“请检查是否满意，不满意可换一张画面”。
- 批量模式下避免在一个屏幕暴露过多儿童敏感信息，列表默认显示称呼和必要素材状态。

## 13. Implementation slices

### Slice 1：统一入口与文案迁移

- 新增 `PersonalizedCreationWorkspace` 容器。
- Dashboard 文案改为“创建专属绘本”。
- `/customize` 路由改为重定向或轻适配。
- 直接创作沿用现有 `PersonalizedStorybookPage` 能力，迁入统一容器。

验收：

- 用户能从工作台进入统一入口。
- 两种起点清晰可选。
- 普通绘本创建入口不受影响。

### Slice 2：对象与素材页

- 落地 `ObjectAndMaterialsForm`。
- 直接创作支持想法、对象称呼、候选素材和锁定素材。
- 来源书起点支持来源书列表、来源摘要、单人选择和批量选择。
- 照片入口先可接 mock 状态，但 UI 状态必须完整。

验收：

- 没有照片也能继续。
- 第 6 张照片不能上传，必须提示最多 5 张。
- 来源书列表能显示可定制、仍在制作和需要处理的原因。
- 已确认照片但无视觉参考时不能制作。
- 批量对象未确认主素材或 `name_only` 时不能继续。

### Slice 3：故事预览

- 直接创作展示 3 方向和 6 页走向。
- 来源书定制展示变化计划和可选保持页。
- 未落点素材阻断制作。

验收：

- 方向数量固定为 3。
- 6 页走向由服务端返回。
- 可选保持页重算期间主动作禁用。

### Slice 4：制作与恢复

- 用 run 状态替换本地生成状态。
- 四阶段进度统一。
- 支持离开恢复、失败重试、取消和素材撤销恢复。

验收：

- 刷新后按 `run_id` 恢复。
- 失败项可重试。
- 撤销素材后必须显式选择恢复动作。

### Slice 5：修改与交付

- 新增 `/review` 子视图。
- 展示本次素材落点和 evidence。
- 批量结果进入单本 review 时携带或恢复 `run_item_id`，用于定位本次输出、证据和问题页。
- 支持满意、改文字、换图和导出门禁。

验收：

- evidence 缺失时导出按钮不可直接导出。
- 问题按钮能定位到对应页面。
- 来源书定制能看到原书对照和本次更新。

### Slice 6：批量结果

- 批量仅来源书起点开放，最多 30 人。
- 结果页按对象展示成功、失败、需补素材、已排除。
- 成功对象可进入单本 review，失败对象可补素材、重试或放弃。

验收：

- 部分失败不回滚成功项。
- 失败对象不阻塞成功对象导出。

## 14. QA checklist

- [ ] 工作台、绘本详情和旧定制路由都进入统一专属绘本创作体验。
- [ ] 直接创作和来源书定制共享四步骨架，但页面内容符合各自起点。
- [ ] 想法少于 8 个有效字符时给出友好修正提示。
- [ ] 直接创作固定展示 3 个方向。
- [ ] 选定方向后才展示 6 页走向。
- [ ] 照片必须确认用途后才生成本次创作素材引用。
- [ ] 本次创作最多上传 5 张真实照片，达到上限后上传入口禁用并说明原因。
- [ ] 已确认使用的照片必须有同画风视觉参考确认。
- [ ] 未落点素材存在时不能开始制作。
- [ ] 来源书定制不要求用户重新输入故事想法。
- [ ] 来源书定制明确说明母本不被修改。
- [ ] 可选页“尽量保持”触发服务端重算。
- [ ] 批量模式每个对象必须确认主素材或仅使用称呼。
- [ ] 批量成功对象进入 review 时能按 `run_item_id` 定位本次输出和证据。
- [ ] 制作进度只显示四个用户可理解阶段。
- [ ] 制作失败、取消、离开恢复和重试都以服务端 run 为准。
- [ ] 撤销照片引用后显示三种恢复动作。
- [ ] 修改与交付页能看到实际素材落点。
- [ ] evidence 缺失时导出入口变为问题处理入口。
- [ ] 连续点击主动作不会产生重复计划、重复运行或重复页级任务。

## 15. Open UI risks

1. 照片视觉参考可能生成较慢，需要后端提供可恢复状态，否则用户会误以为上传卡死。
2. 来源书变化计划如果缺少原页缩略图，用户很难理解“保持”和“重绘”的差异。
3. 批量模式最多 30 人，移动端表格密度需要单独验收，避免主素材确认被折叠到用户找不到。
4. evidence 缺失是技术事实，但前端文案必须翻译成用户能处理的问题，例如“第 3 页缺少红色小汽车的素材记录”。
5. 现有 `PersonalizedStorybookPage` 和 `CustomizeStorybookPage` 已有不少本地状态，迁移时要先建立统一状态映射，避免一边接 session、一边接 generation job 造成恢复逻辑分裂。
