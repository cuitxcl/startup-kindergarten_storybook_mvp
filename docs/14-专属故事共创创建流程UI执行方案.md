# 专属故事共创创建流程 UI 执行方案

## 1. 方案定位

本方案用于重构“创建绘本”体验。产品定位不再是单一的“幼儿园老师绘本生成工具”，而是：

> 私人定制故事共创平台。

老师仍然可以作为第一批突破用户，但 UI 不应被“班级/幼儿园/教学后台”完全锁死。底层流程要能扩展到家长、课程机构、生日纪念、品牌/IP 故事和自由创作。

本次 UI 的核心目标是让用户觉得：

- 我可以很快开始。
- AI 理解了我的真实动机。
- 我在关键节点参与了创作选择。
- 成品明显使用了我的专属素材。
- 我不用懂 prompt、模型、任务队列，也能完成一本作品。

## 2. 核心产品判断

### 2.1 要保留的三个关键瞬间

1. **系统理解我**
   用户输入一句想法后，系统要用一句话复述理解，并展示识别出的素材。

2. **我选择方向**
   系统给 3 个故事方向，用户选择其中一个。用户不是在审稿，而是在做创作决策。

3. **我确认大纲**
   生成完整故事前，用户先看到 6-8 页走向。大纲页用于建立预期，不是强迫逐页编辑。

### 2.2 要避免的问题

- 不让用户在第一步卡住。
- 不让用户以为每一步都必须编辑。
- 不让验收变成逐页打卡任务。
- 不把高级设置做成 AI 参数面板。
- 不在主流程中暴露 job、provider、prompt schema、参考图权重等技术语言。
- 不强制所有用户确认主角形象；只有高度定制场景才触发。

## 3. 顶层流程

顶部进度只显示 5 步：

```text
想法 -> 方向 -> 大纲 -> 生成 -> 验收
```

每一步只有一个主要任务：

| 步骤 | 用户心智 | 页面目标 | 主按钮 |
| --- | --- | --- | --- |
| 想法 | 我想做一个什么故事 | 快速开始，不会写也能继续 | 开始生成方向 |
| 方向 | AI 懂了，我选一个角度 | 让用户做一次关键选择 | 按这个方向继续 |
| 大纲 | 先看看故事怎么展开 | 建立预期，不强制编辑 | 就按这个生成 |
| 生成 | 一键做成完整作品 | 故事和画面生成，低权重设置 | 开始生成整本绘本 |
| 验收 | 看一遍，只改不满意的 | 浏览、重画、导出/分享 | 完成作品 |

## 4. 路由建议

第一版可继续复用：

```text
/app/:workspaceId/storybooks/new
```

如果后续要弱化“storybook”命名，可新增别名路由：

```text
/app/:workspaceId/stories/new
```

但前端实现第一版不需要强制改后端资源名。

## 5. 页面一：想法

### 5.1 页面目的

让用户用最低成本开始，并把“创作动机”放在最前面。

### 5.2 页面结构

顶部：

- 进度：`想法`
- 小字空间归属：`创建在 {workspace.name}`

主体：

- 标题：`想做一本什么故事？`
- 副标题：`说一句也可以，我们会帮你整理成故事方向。`
- 大输入框
- 示例起点卡片
- 主按钮

### 5.3 输入框

Label：

```text
故事想法
```

Placeholder：

```text
给 4 岁的乐乐，他最近不太愿意分享红色小汽车，想做一本温柔的小故事。
```

输入规则：

- 支持一句话继续。
- 最少建议 8 个中文字符。
- 为空时主按钮禁用，并提示：`先写一句想法，或选择下面的示例开始。`

### 5.4 示例起点

示例起点用卡片，不用简单标签。点击后把可编辑模板填入输入框。

| 卡片 | 说明 | 点击后填入示例 |
| --- | --- | --- |
| 孩子成长 | 帮孩子理解分享、等待、情绪表达 | 给一个 4 岁孩子做一本关于分享和轮流的温柔故事。 |
| 班级教育 | 做一本文明排队、午睡、活动规则故事 | 给一个幼儿园班级做一本关于排队等待的规则故事。 |
| 生日纪念 | 记录一个人的成长、回忆和祝福 | 给一个孩子做一本生日纪念故事，记录成长和祝福。 |
| 课程故事 | 为课程主题生成一个配套故事 | 做一本适合课堂导入的环保主题故事。 |
| 自由创作 | 直接描述你想要的故事 | 我想自由创作一本温暖、有想象力的故事。 |

第一版建议展示前 5 个；后续可增加 `品牌/IP 故事`，但不作为首屏重点。

注意：

- `生日纪念`、`课程故事`、`自由创作` 不应默认套入儿童或幼儿园语境。
- 示例卡每张最多两行说明，移动端单列展示，避免第一屏变成模板库。
- 卡片点击后只填入可编辑示例，不直接提交，用户仍可修改。

### 5.5 主操作

主按钮：

```text
开始生成方向
```

点击后：

1. 保存用户原始想法。
2. 请求 AI 生成意图理解、素材 chips、3 个故事方向。
3. 进入“方向”页。

### 5.6 状态

| 状态 | UI 表现 |
| --- | --- |
| 空状态 | 展示示例起点，按钮禁用 |
| 输入过短 | 输入框下提示：`再补充一点对象或目的，会更容易生成方向。` |
| 生成中 | 按钮显示 `正在整理方向...`，输入框不可编辑或保留只读 |
| 失败 | 顶部或输入框下显示：`方向生成失败，可以重试。` 按钮：`重试` |

## 6. 页面二：方向

### 6.1 页面目的

合并“AI 理解、素材识别、故事方向选择”。页面主任务是选方向，不是审理解。

### 6.2 页面结构

顶部轻摘要：

```text
我理解：给乐乐做一本关于分享红色小汽车的温柔故事
```

素材 chips：

```text
乐乐  红色小汽车  分享  轮流  温柔
```

展示规则：

- 单个 chip 最多显示 10 个中文字符，超出后截断为 `...`。
- 一行最多展示 5 个 chips，更多内容合并为 `+N`。
- 点击 `+N` 或素材区域可展开完整素材列表。
- 素材不足时不使用“专属”措辞，只提示用户可以补充真实细节。

右侧或同一行低权重操作：

```text
补充
```

主体：

- 3 个故事方向卡片。
- 每张卡片固定结构，避免信息量不一致。

底部 sticky：

- 未选中方向：不显示主按钮，或按钮禁用。
- 选中方向后：显示主按钮 `按这个方向继续`。

### 6.3 方向卡片结构

每张卡片包含：

```text
标题
一句话剧情
适合：分享 / 情绪 / 规则
将使用：乐乐、红色小汽车、轮流
```

示例：

```text
小汽车轮流站
乐乐和朋友都想玩红色小汽车，老师把等待变成一个轮流游戏。
适合：温柔引导分享
将使用：乐乐、红色小汽车、轮流
```

按钮：

```text
选这个
```

选中后：

- 卡片高亮。
- 其他卡片保持可切换。
- 底部主按钮变为可点击。

### 6.4 辅助操作

`补充`

- 打开轻量输入框。
- Placeholder：`补充一个真实细节，例如：发生在星星班午睡室。`
- 提交后刷新理解摘要、素材 chips 和方向。

`换一批`

- 保留用户输入和素材。
- 重新生成 3 个方向。
- 不清空已补充素材。

第一版不提供“跳过方向选择”。方向选择是参与感核心，用户必须选择一个方向后才能进入大纲页。

### 6.5 状态

| 状态 | UI 表现 |
| --- | --- |
| 加载中 | 方向卡骨架屏 3 张 |
| 无方向 | 显示 `暂时没有整理出方向，可以补充一句真实细节。` |
| 生成失败 | 保留原始想法，按钮 `重新生成方向` |
| 素材少 | 提示 `可以补充名字、地点或真实细节，让故事更像你们。` |
| 素材足够 | 提示 `已形成专属素材：{chips}` |

## 7. 页面三：大纲

### 7.1 页面目的

给用户生成前的预期感和掌控感。默认鼓励继续生成，不强制精修。

### 7.2 页面结构

标题：

```text
故事会这样展开
```

副标题：

```text
先看走向，满意就直接生成完整故事。
```

主体：

- 6-8 页大纲列表或分页预览。
- 默认不显示复杂编辑器。
- 每页只展示一句大纲。

底部：

- 素材摘要。
- 主按钮。
- 辅助按钮。

### 7.3 大纲列表

示例：

```text
1 乐乐带来红色小汽车
2 朋友也想玩
3 乐乐有点舍不得
4 老师提出轮流游戏
5 大家开始等待
6 乐乐发现分享很开心
```

每条可带轻量素材标记：

```text
1 乐乐带来红色小汽车  [乐乐] [红色小汽车]
4 老师提出轮流游戏  [轮流]
```

### 7.4 操作

主按钮：

```text
就按这个生成
```

辅助按钮：

```text
换个结尾
返回换方向
```

每页操作：

- 默认隐藏。
- hover 或点开当前页后显示 `调整这一页`。
- 移动端点击当前页后展开操作。

`调整这一页` 不打开完整编辑器，先显示快捷项：

```text
更短一点
更温柔
更有趣
换个情节
补充要求
```

### 7.5 状态

| 状态 | UI 表现 |
| --- | --- |
| 加载中 | 大纲时间线骨架 |
| 大纲生成失败 | 显示失败说明，按钮 `重新生成大纲` |
| 修改中 | 当前页显示内联 loading，其他页可读 |
| 修改成功 | 当前页短暂显示 `已更新` |

## 8. 页面四：生成

### 8.1 页面目的

把故事和画面生产合并成一个作品生成阶段。用户感知是“一键生成整本绘本”，不是多个技术任务。

### 8.2 页面状态一：生成前准备态

标题：

```text
准备生成这本专属绘本
```

摘要：

```text
故事：乐乐学会分享红色小汽车
页数：6 页 + 封面
画面：水彩 · 简单清楚 · 自动保持角色一致
```

定制命中提示：

```text
将使用：乐乐、红色小汽车、轮流、温柔
```

主按钮：

```text
开始生成整本绘本
```

低权重入口：

```text
调整画面
```

### 8.3 画面调整抽屉

入口文案不要叫 `高级设置`，使用：

```text
调整画面
```

第一层只放用户能理解的选项：

| 设置 | 选项 |
| --- | --- |
| 画风 | 水彩、蜡笔、扁平插画、黏土、国风 |
| 画面复杂度 | 简单清楚、标准、细节丰富 |
| 角色一致性 | 自动保持一致、优先速度、先让我确认主角形象 |
| 生成范围 | 整本生成、只补缺失、当前页 |

移动端规则：

- 抽屉从底部弹出，最高不超过视口 85%。
- 4 组设置按分组折叠展示，默认展开 `画风` 和 `画面复杂度`。
- 底部固定显示当前摘要和 `保存设置` 按钮。
- 不允许设置项横向滚动；选项按钮可换行。

抽屉底部展示摘要：

```text
当前：水彩 · 简单清楚 · 自动保持角色一致 · 整本生成
```

二级入口：

```text
更多专业选项
```

默认收起。第一版可不实现，或只预留入口。

### 8.4 主角形象模块

主角形象确认不作为独立步骤，只作为生成页内的可选模块。

触发条件：

- 用户上传照片。
- 用户填写明确主角。
- 用户选择 `先让我确认主角形象`。
- 系统检测到主角贯穿多页且角色一致性要求高。

默认表现：

```text
主角形象
已自动生成，可直接使用
查看/更换
```

点击 `查看/更换` 后展示 2-3 张候选图：

```text
用这个
换一组
描述更像一点
```

### 8.5 页面状态二：生成中

标题：

```text
正在把故事画出来
```

总进度：

```text
3 / 7
```

动态文案必须带入用户素材：

```text
正在画乐乐和红色小汽车
正在生成轮流游戏这一页
正在完成封面
```

任务列表使用作品语言：

```text
封面    生成中
第 1 页 完成
第 2 页 等待
第 3 页 等待
```

不要显示：

- job id
- provider
- prompt
- queue name
- raw JSON

失败状态：

```text
第 3 页生成失败
```

操作：

```text
重试这一页
跳过，稍后处理
```

## 9. 页面五：验收

### 9.1 页面目的

让用户浏览整本作品，只处理不满意的地方。不要强制逐页点通过。

### 9.2 桌面布局

三栏：

1. 左侧：页面缩略图。
2. 中间：当前页大预览。
3. 右侧：当前页文字、素材命中、操作。

布局权重：

- 中间预览列优先，桌面宽度低于 1180px 时右侧操作区收窄。
- 桌面宽度低于 980px 时切换为单列布局。
- 右侧操作区不能比预览区更抢视觉；重画和编辑文字使用次级按钮。

### 9.3 移动端布局

单列：

1. 顶部页码切换。
2. 中间大图预览。
3. 下方当前页文字。
4. 底部 sticky 操作栏。

### 9.4 页面操作

每页默认操作：

```text
重画
编辑文字
```

不要默认要求 `通过`。

可以提供轻量正反馈：

```text
这一页很好
```

但不是完成前必填。

全局主按钮：

```text
全部看过，完成作品
```

如果仍有未查看页面：

```text
还有 3 页未查看，也可以先完成，稍后继续修改。
```

导出/分享前建议提示：

```text
建议至少预览封面和第 1 页，再导出或分享。
```

该提示不阻断完成作品，但在用户未查看封面或第 1 页时展示。

### 9.5 重画弹层

标题：

```text
哪里不合适？
```

原因按钮：

```text
人物不像
画面太复杂
不符合文字
表情不对
换个构图
```

补充输入：

```text
补充要求，可不填
```

主按钮：

```text
重新生成这一页
```

### 9.6 完成态

完成不是独立步骤，而是验收页内状态。

完成后右侧或底部显示：

```text
作品完成
《乐乐和红色小汽车》
一本为乐乐定制的分享主题故事
```

定制命中提示：

```text
这本故事使用了 4 个专属素材：乐乐、红色小汽车、轮流、温柔
```

操作：

```text
预览
导出 PDF
分享链接
继续做下一本
```

## 10. 定制命中提示机制

这是本方案新增的关键机制，用于解决“用户感觉只是把名字塞进去”的问题。

### 10.1 触发原则

当用户输入里包含可识别的真实元素时，系统应持续展示这些元素如何进入作品。

可识别素材包括：

- 人名/角色名
- 年龄
- 地点
- 喜欢的物品
- 真实事件
- 想传达的话
- 情绪/语气
- 关系

### 10.2 展示位置

| 页面 | 展示方式 |
| --- | --- |
| 方向页 | `这个方向会使用：乐乐、红色小汽车、轮流` |
| 大纲页 | 在相关页旁标记素材 chip |
| 生成页 | 动态文案带入素材 |
| 验收完成态 | `这本故事使用了 4 个专属素材：...` |

### 10.3 素材少时的文案

不要过早承诺“专属”。

素材少时：

```text
可以补充名字、地点或真实细节，让故事更像你们。
```

素材足够时：

```text
已形成专属素材：乐乐、红色小汽车、轮流。
```

## 11. 组件拆分

建议前端沉淀以下组件：

| 组件 | 责任 |
| --- | --- |
| `CreationProgress` | 顶部 5 步进度 |
| `IntentStartPanel` | 想法输入和示例起点 |
| `ExampleStartCards` | 场景示例卡 |
| `UnderstandingSummary` | 一句话 AI 理解 |
| `MaterialChips` | 已识别/已使用素材 |
| `StoryDirectionCards` | 3 个方向选择 |
| `OutlineReviewList` | 大纲预览和轻量调整 |
| `GenerationComposer` | 生成前摘要和主按钮 |
| `ImagePreferenceDrawer` | 画面设置抽屉 |
| `OptionalCharacterPicker` | 可选主角形象确认 |
| `GenerationProgressList` | 作品生成进度 |
| `BookReviewWorkspace` | 验收工作台 |
| `RegenerateReasonModal` | 重画原因弹层 |
| `CompletionPanel` | 验收页完成态 |

## 12. 数据需求

前端页面至少需要这些结构。字段名为 UI 语义，后续可映射到真实 API。

### 12.1 创作会话

```ts
type CreationSession = {
  id: string;
  workspaceId: string;
  step: "intent" | "direction" | "outline" | "generation" | "review";
  status: "draft" | "generating" | "ready_for_review" | "completed" | "failed";
  rawIntent: string;
  sceneType?: "child_growth" | "classroom" | "birthday" | "course" | "free";
  understanding?: string;
  materials: CreationMaterial[];
  directions: StoryDirection[];
  selectedDirectionId?: string;
  outline: StoryOutlinePage[];
  visualPreferences: VisualPreferences;
  generationStatus?: GenerationStatus;
  lastError?: string;
  completedSteps: Array<"intent" | "direction" | "outline" | "generation" | "review">;
  storybookId?: string;
  createdAt: string;
  updatedAt: string;
};
```

### 12.2 素材

```ts
type CreationMaterial = {
  id: string;
  label: string;
  type: "person" | "place" | "object" | "event" | "message" | "tone" | "relationship";
  source: "user_input" | "ai_extracted" | "user_added";
  confidence?: number;
};
```

### 12.3 故事方向


### 12.7 状态恢复要求

- 刷新页面后应能恢复当前创作阶段、原始想法、已选方向、大纲和生成进度。
- 如果第一版暂不持久化 `CreationSession`，至少要把草稿保存在当前 storybook 记录或 local storage，并在文案中避免承诺“随时恢复”。
- 一旦进入生成阶段，应以后端 storybook / generation jobs 作为恢复依据，避免仅依赖前端内存。
- `materials`、`directions`、`outline` 如果不能落库，需要明确映射到 storybook metadata 或生成结果 payload，避免进入详情页后丢失“定制命中提示”。

## 13. 状态矩阵

| 状态 | 想法 | 方向 | 大纲 | 生成 | 验收 |

## 14. 文案规范

### 14.1 使用创作语言

推荐：

- `开始生成方向`
- `故事会这样展开`
- `正在把故事画出来`

避免：

- `创建 generation job`
- `提交任务`
- `确认 schema`

## 15. 响应式规则

### 15.1 桌面

- 主内容最大宽度控制在 1040-1180px。
- 想法、方向、大纲使用单列居中。
- 验收页可使用三栏，但中间预览优先。
- 底部主按钮可 sticky，避免滚动后找不到下一步。

### 15.2 移动端

- 所有页面单列。
- 方向卡纵向排列。
- 大纲页只展示页号 + 一句摘要。
- 验收页使用：
  - 顶部页码切换
  - 中间大图
  - 下方文字
  - 底部 sticky 操作栏
- 每屏只出现一个明显主按钮。
- 按钮文字允许换行，但不能撑出横向滚动。

## 17. 验收标准

### 17.1 体验验收

- 用户可以只输入一句话进入方向页。
- 用户可以点击示例起点自动填入想法。
- 方向页主视觉是 3 个方向卡，不是大段 AI 解释。
- 未选方向时不能继续。
- 大纲页默认主按钮是 `就按这个生成`。
- 大纲页不要求用户逐页编辑。
- 生成页默认不展示技术字段。
- 生成进度文案至少一次带入用户素材。
- 验收页不强制每页点击 `通过`。
- 完成态展示作品标题和已使用素材。

### 17.2 UI 验收

- 每个页面只有一个最高权重主按钮。
- 辅助操作不超过 2 个，更多操作进入抽屉或折叠。
- 移动端 390px 无横向滚动。
- 主按钮在移动端可见或 sticky。
- 长标题、长素材 chip、长按钮文案不会撑破容器。
- 生成失败和单页重画失败都有可恢复操作。

### 17.3 产品验收

- 用户 3 分钟内能进入生成阶段。
- 用户至少完成一次主动选择：故事方向。
- 成品里能看到用户输入的真实素材。
- 用户不用编辑 prompt 也能完成重画。
- 素材不足时，页面不会强行宣称“专属”。

## 18. 实施顺序建议

1. 先重构前端状态模型：把当前五步生成向导映射为 `intent/direction/outline/generation/review`。
2. 先做静态 UI 和 mock 数据，跑通 5 步页面切换。
3. 接入现有故事方案生成能力，产出理解摘要和方向卡。
4. 接入现有分页生成能力，产出大纲和完整故事。
5. 接入整本生图按钮和生成进度。
6. 改造详情/验收页，弱化逐页通过，保留重画和编辑文字。
7. 最后补移动端和失败恢复。

## 19. 实现前需补充的工程边界

以下边界必须在正式实现前确认，否则容易出现 UI 已完成但流程无法恢复或数据无法映射的问题。

### 19.1 CreationSession 是否持久化

推荐：持久化。

最低要求：

- `rawIntent`、`understanding`、`materials`、`selectedDirectionId`、`outline`、`visualPreferences` 至少能在刷新后恢复。
- 若第一版只做前端本地草稿，需要在用户离开页面前提示未保存风险。

### 19.2 素材 chips 是否可编辑

第一版建议：

- AI 自动抽取。
- 用户可以新增和删除。
- 用户不需要编辑素材类型。

后续再考虑：

- 修改素材类型。
- 标记素材重要程度。
- 为素材绑定图片或参考资料。

### 19.3 方向和大纲如何保存

推荐：

- 方向和大纲在生成 storybook 前属于 `CreationSession`。
- 生成 storybook 后，大纲映射为 storybook pages，方向和素材进入 storybook metadata 或 generation summary。
- 详情/验收页仍能读取已使用素材，用于完成态展示。

### 19.4 现有接口适配

如果后端暂不新增接口，前端需要 adapter：

- 现有“故事方案”结果映射为 `understanding + directions`。
- 现有“分页生成”结果映射为 `outline + pages`。
- 现有 generation jobs 映射为 `GenerationStatus.steps`。

如果现有接口无法稳定产出 3 个方向和大纲，则第一阶段应先用 mock adapter 跑通 UI，再补 API。

### 19.5 生成中断恢复

必须定义：

- 生成中刷新页面后展示哪个阶段。
- 某一页图片失败后是否允许进入验收。
- `跳过，稍后处理` 后该页在验收页如何标记。
- 生成完整故事成功但图片失败时，主按钮显示 `继续生成插图`，而不是重新开始。

### 19.6 第一版固定产品决策

- 不允许跳过方向选择。
- 不强制确认主角形象。
- 不强制逐页通过。
- 不暴露专业 prompt 或 provider 设置。
- 不把生日纪念、课程故事、自由创作写成幼儿园专属模板。

## 20. 开放问题

- 是否把“绘本”在 UI 文案中改为“故事作品”，只在导出/封面场景使用“绘本”？
- 大纲页是否固定 6 页，还是根据年龄/场景自动决定页数？
- 生成完整故事和生成插图是否拆成两个真实后台阶段，还是前端合并展示？

## 21. 最终设计原则

一句话开始，三个方向参与，大纲建立预期，一键生成作品，轻量验收问题页。

UI 要始终让用户感受到：

> 我说的话，真的变成了这本故事的一部分。
