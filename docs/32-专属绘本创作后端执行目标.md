# 专属绘本创作后端执行目标

> 来源文档：`docs/29-专属绘本创作统一实施说明.md`、`docs/30-专属绘本创作UI执行方案.md`、`docs/31-专属绘本创作后端落地执行方案.md`。  
> 用途：作为后端落地任务的目标说明，可直接交给后端工程师或 Codex 后端任务执行。  
> 总原则：不重写现有专属绘本直接创作主干，只补齐真实照片资产、资产引用、同画风视觉参考、刷新恢复和最终生成门禁。

## 0. 后端目标卡

### 目标标题

专属绘本创作 Phase 1：照片资产引用与同画风视觉参考闭环。

### 一句话目标

让专属绘本创作中的真实照片从“前端临时状态”变成“后端可恢复、可鉴权、可追踪、可门禁的业务资产”，并确保最终绘本生成只读取已确认的视觉参考。

### 成功定义

后端完成后，前端应能不依赖本地 mock 状态完成以下闭环：

```text
创建专属绘本 session
-> 上传真实照片
-> 服务端创建 asset 与 asset_reference
-> 用户填写参考图名称和用途
-> 服务端创建同画风 visual_reference 生成任务
-> 用户确认 visual_reference
-> 生成方向和大纲时可带 warnings 继续预览
-> 最终 storybook:generate 只允许 confirmed 视觉参考入队
-> 页面刷新后完整恢复上述状态
```

### 本次必须交付

- 新增照片资产、创作资产引用、同画风视觉参考的数据表、模型和 repository。
- 新增上传策略、照片上传、用途更新、参考图生成、参考图确认、撤销引用、预览鉴权接口。
- 扩展 creation session 响应，返回 `asset_references`、嵌套 `asset`、嵌套 `visual_reference`。
- 接入 generation job，支持视觉参考生成成功、失败、重试和确认。
- 接入 `directions:generate` / `outline:generate` 软门禁 warnings。
- 接入 `storybook:generate` 强门禁和 generation input snapshot 冻结。
- 补齐权限、幂等、5 张上限、非法文件、刷新恢复和端到端 smoke 验证。

### 本次明确不做

- 不重写 `storybook_creation_sessions` 主流程。
- 不做批量定制。
- 不做来源书变化计划。
- 不做 review/evidence 完整交付页。
- 不做公共素材库沉淀。
- 不做人脸身份识别或相似度承诺。

### 交付验收命令

后端任务交付前至少需要通过：

```bash
cd server && cargo fmt --all --check
cd server && cargo check
cd server && cargo test
scripts/smoke-storybook-creation-assets.sh
scripts/smoke-storybook-creation-ui.sh
```

其中 `scripts/smoke-storybook-creation-ui.sh` 需要证明“页面上传照片入口 -> 服务端 asset policy / upload -> 用途确认 -> 视觉参考确认 -> 浏览器刷新恢复”链路可用。

## 1. 可直接开启的后端目标

请根据 `docs/31-专属绘本创作后端落地执行方案.md` 落地专属绘本创作 Phase 1 后端能力。

目标是在现有 `storybook_creation_sessions` 主流程旁边补齐照片素材闭环，让前端不再依赖本地 mock 状态，而是由服务端保存和恢复以下流程：

```text
创建 creation session
-> 上传真实照片
-> 创建本次创作 asset reference
-> 确认照片用途和显示名称
-> 生成同画风 visual reference
-> 用户确认 visual reference
-> 允许进入最终 storybook:generate
```

Phase 1 的交付标准是跑通“单本专属绘本 + 最多 5 张真实照片 + 刷新可恢复 + 最终制作强门禁”。不要在本任务中扩展批量定制、来源书变化计划、review/evidence 完整交付页或公共素材库。

## 2. 构建假设

- 现有直接创作主干已经可用，包括创建会话、恢复会话、生成方向、生成大纲和 `storybook:generate` 入队。
- `session` 是创作草稿真相；照片相关状态必须跟随 session 恢复。
- `asset` 只代表上传文件；真正参与创作的是 `asset_reference`。
- 原始照片默认只属于本次创作，不进入公共素材库、空间素材库或模板素材。
- 选择“使用”的照片必须完成同画风视觉参考确认后，才能进入最终绘本制作。
- 删除照片的 Phase 1 语义是撤销本次创作引用，不是物理删除原始文件。
- 所有影响生成输入的资产变更，都必须让已有方向和大纲失效。
- 所有读写都必须同时校验 `workspace_id` 和 `creation_session_id`。

## 3. 必须复用的现有主干

不要重写以下模块，只在旁边增补资产能力并接入门禁：

- `server/src/controllers/storybook_creation.rs`
- `server/src/application/storybook_creation.rs`
- `server/src/repositories/storybook_creation_sessions.rs`
- `server/migration/src/m20260814_000021_create_storybook_creation_sessions.rs`

继续复用现有接口：

- 创建、恢复、更新 creation session。
- `directions:generate`
- `outline:generate`
- `storybook:generate`
- generation job 入队与幂等生成逻辑。

## 4. 依赖链

```text
Schema / migration
-> Rust models / DTO
-> asset repository
-> session response 扩展
-> 上传与资产引用 API
-> visual reference job 与状态写回
-> directions / outline 软门禁
-> storybook:generate 强门禁与 input snapshot
-> API / repository / storage 测试
```

实现时必须优先保证数据模型和状态机稳定，再接接口和生成门禁。

本任务的最小完成定义不是“接口能返回”，而是后端成为照片素材流程的业务真相：刷新页面、重复点击、撤销、失败重试、最终生成门禁都不能依赖前端本地状态兜底。

## 5. Phase 1 必做范围

### 5.1 Schema 与模型

新增三类业务对象：

- `storybook_assets`：原始上传文件。
- `storybook_asset_references`：照片在本次创作里的业务引用。
- `storybook_visual_references`：由真实照片生成的同画风参考图。

关键字段必须覆盖：

- `workspace_id`
- `creation_session_id`
- `uploaded_by`
- `storage_key`
- `original_filename`
- `content_type`
- `byte_size`
- `width`
- `height`
- `asset.status`
- `processing_message`
- `visibility_scope=creation_session`
- `retention_policy=session_scoped`
- `asset_reference.kind`
- `asset_reference.usage`
- `asset_reference.display_name`
- `asset_reference.status`
- `asset_reference.material_id`
- `visual_reference.status`
- `visual_reference.generation_job_id`
- `visual_reference.image_storage_key`
- `visual_reference.confirmed_at`
- `visual_reference.confirmed_by`

### 5.2 权限与隐私

Phase 1 默认权限：

- 只有 session 创建者和 `SchoolAdmin` 可以操作创作资产。
- 普通编辑者不能接管他人创建的 session。
- 只读成员不能查看原图、修改用途或确认视觉参考。
- 预览 URL 必须鉴权，不能返回永久公开对象地址。

隐私规则：

- 原始照片默认只用于本次创作。
- `unused` / `revoked` 引用不进入 generation input。
- 原始 asset 若无 active reference，可进入后台清理候选，默认 30 天。
- 已生成参考图和最终产物属于生成证据链，不因撤销本次引用立即物理删除。

### 5.3 API

必须实现以下接口：

```http
GET /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-upload-policy
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/assets
PATCH /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}/visual-reference:generate
POST /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/visual-references/{visual_reference_id}/confirm
DELETE /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/asset-references/{asset_reference_id}
GET /api/workspaces/{workspace_id}/storybook-creation-sessions/{session_id}/assets/{asset_id}/preview
```

必须扩展 `StorybookCreationSession` 响应：

- `asset_references[]`
- 嵌套 `asset`
- 嵌套 `visual_reference`

刷新恢复时前端必须能拿到：

- `asset.status`
- `processing_message`
- `content_type`
- `byte_size`
- `width`
- `height`
- `asset_reference.kind`
- `asset_reference.usage`
- `asset_reference.display_name`
- `asset_reference.status`
- `visual_reference.status`
- `visual_reference.preview_url`

### 5.4 文件上传规则

- 支持 `image/jpeg`、`image/png`、`image/webp`。
- 单文件默认最大 10 MB，允许通过配置调整。
- 每个 creation session 最多 5 张非 `revoked` / `unused` 的有效照片。
- 后端必须校验真实文件头或文件内容，不能只信任前端 MIME。
- 原文件名只用于显示和排查，业务名使用 `display_name`。

### 5.5 状态映射

`visual_reference.status` 是任务真实状态，`asset_reference.status` 是创作流程聚合状态。

后端必须统一维护以下映射：

| asset_reference.status | 触发条件 |
| --- | --- |
| `awaiting_usage` | 未选择用途，且未撤销。 |
| `unused` | 用户选择本次不使用。 |
| `revoked` | 本次创作引用已撤销。 |
| `awaiting_reference` | 已选择使用，但没有 active visual reference，或参考图仍在 `queued/generating`。 |
| `awaiting_confirmation` | active visual reference 已生成，等待用户确认。 |
| `ready` | active visual reference 已确认。 |
| `failed` | active visual reference 生成失败。 |

约束：

- 同一 `asset_reference_id` 最多只能有一个 active visual reference。
- 重新生成视觉参考时，旧的待确认参考必须标记为 `rejected` 或转为非 active。
- 最终门禁读取服务端聚合后的 `asset_reference.status`，不能让前端自行推断。

## 6. 生成门禁

### 6.1 软门禁

`directions:generate` 和 `outline:generate` 允许先继续，但如果存在未处理照片，响应必须在 `meta.warnings` 返回待处理信息。

warning 结构建议：

```json
{
  "code": "visual_reference_pending",
  "message": "1 张照片还没有确认同画风参考，开始制作前需要处理。",
  "asset_reference_ids": ["uuid"],
  "next_action": "confirm_visual_reference"
}
```

### 6.2 强门禁

`storybook:generate` 必须阻断以下状态：

- `awaiting_usage`
- `awaiting_reference`
- `awaiting_confirmation`
- `failed`

不阻断：

- `ready`
- `unused`
- `revoked`

阻断时返回可行动错误，例如：

```json
{
  "error": {
    "code": "visual_reference_required",
    "message": "先确认 1 张照片的同画风参考，再开始制作。",
    "details": {
      "blocking_asset_reference_ids": ["uuid"],
      "next_action": "confirm_visual_reference"
    }
  }
}
```

最终 `creation_storybook_generate.input_json` 必须包含：

- confirmed asset references
- confirmed visual references
- `asset_reference_id`
- `visual_reference_id`
- `material_id`
- `confirmed_at`
- `visibility_scope`
- `retention_policy`

## 7. 与 CreationMaterial 的关系

照片引用不能替代 `CreationMaterial`，必须生成或关联一个 material：

- `CreationMaterial.source = "asset_reference"`
- `CreationMaterial.label = display_name`
- `kind=person` 映射为 `character`
- `kind=object` 映射为 `object`
- `kind=scene` 映射为 `scene`
- `CreationMaterial.locked = true`
- `asset_reference.material_id` 指向该 material

用户改名、改用途、撤销或改为不用时，必须让方向和大纲失效，避免旧计划继续使用错误素材。

## 8. 建议开工顺序

### Phase 0：契约审计

目标：确认当前前端 UI 与现有后端字段差异。

任务：

- 梳理前端专属绘本页面需要的 session 字段。
- 对照 `StorybookCreationSession` 响应，列出缺字段。
- 确认现有 generation job 是否能复用视觉参考任务。
- 确认文件存储路径和预览 URL 鉴权方式。
- 确认 `Envelope.meta.warnings` 是否能兼容现有响应。

验收：

- 能说明前端每个照片动作对应哪个 API。
- 明确 session 恢复时需要返回哪些 asset reference 字段。
- 明确 Phase 1 权限和隐私口径。

### Phase 1：Schema、模型与 repository

目标：让照片引用成为数据库真相。

任务：

- 新增三张表 migration。
- 新增 Rust models / DTO。
- 新增 asset repository。
- 实现创建、查询、更新、撤销、确认和状态聚合。
- 保证同一引用最多一个 active visual reference。

验收：

- migration 可执行。
- session 可查回 asset references。
- repository 能返回统一聚合状态。
- 资产默认 `visibility_scope=creation_session`。

### Phase 2：上传与恢复 API

目标：前端可以真实上传照片并刷新恢复。

任务：

- 实现上传策略接口。
- 实现 multipart 上传。
- 校验文件数量、类型、大小。
- 写入本地或对象存储，并返回鉴权预览 URL。
- 实现用途更新和撤销。
- 扩展 session 响应，返回嵌套 asset 和 visual reference。

验收：

- 上传 1 张照片后刷新页面不丢失。
- 第 6 张有效照片返回 `photo_limit_exceeded`。
- 非法类型和超大文件返回稳定错误码。
- 原图预览必须鉴权。

### Phase 3：视觉参考任务

目标：真实接入视觉参考生成状态。

任务：

- 创建或复用 generation job 类型，例如 `storybook_visual_reference`。
- 生成 visual reference 时写入 `generation_job_id`。
- job 成功后写回 `image_storage_key` 和 `awaiting_confirmation`。
- job 失败后写回 `failed` 和可读失败原因。
- 确认参考图后写入 `confirmed`，并同步 asset reference 为 `ready`。

验收：

- 视觉参考状态可从 `queued/generating` 恢复。
- 成功后前端可看到参考图并确认。
- 失败后可重试或改为不用。
- 重复点击不会创建重复 active visual reference。

### Phase 4：门禁与生成输入

目标：最终制作只能读取已确认素材。

任务：

- `directions:generate` / `outline:generate` 返回软门禁 warnings。
- `storybook:generate` 接入强门禁。
- `unused` / `revoked` 不进入 generation input。
- 资产引用变化后失效方向和大纲。
- `creation_storybook_generate.input_json` 冻结 confirmed references。

验收：

- 未确认视觉参考不能成功入队最终绘本生成。
- 已确认参考图可以进入最终生成。
- input snapshot 可追溯本次实际使用的照片引用和视觉参考。

### Phase 5：测试与回归

目标：避免照片状态、权限、幂等和门禁回归。

任务：

- 补 repository 状态映射测试。
- 补上传 API 测试。
- 补权限测试。
- 补最终生成强门禁测试。
- 补 `Envelope.meta.warnings` 兼容测试。
- 跑 `cargo fmt`、`cargo check`、`cargo test`。

验收：

- 所有新增测试通过。
- 现有 storybook creation 主流程不回归。
- 文档验收项能逐项对应代码或测试。

## 9. 最小可交付切片

第一条必须跑通的垂直切片：

```text
创建 session
-> 上传 1 张人物照片
-> 命名为“爸爸”
-> 标记为主角
```

刷新页面后，以上每个中间状态都必须能恢复。

## 13. 建议拆成的工程任务

为了降低返工，建议按下面顺序拆任务，不要把所有内容塞进一次大改：

1. 数据模型任务：新增 migration、models、repository 和状态聚合测试。
2. 上传恢复任务：新增上传策略、multipart 上传、预览鉴权、session 响应扩展。
3. 用途与撤销任务：支持显示名、用途、`CreationMaterial` 关联、方向/大纲失效。
4. 视觉参考任务：接入 generation job、写回状态、确认参考图、失败重试。
5. 生成门禁任务：directions/outline warnings、storybook:generate 强门禁、input snapshot 冻结。
6. 验收任务：补权限、幂等、5 张上限、非法文件、刷新恢复和端到端 smoke。

每个任务完成后系统都应该仍然可启动、可测试；不要为了后续阶段提前引入批量定制或来源书变化计划。

## 14. 主要实现风险

- 视觉参考 job 如果只创建记录但没有 worker 写回，会导致前端永远停在处理中。
- `asset_reference.status` 如果由前端推断，最终门禁容易和 UI 状态不一致。
- 预览 URL 如果直接暴露文件路径或公共对象地址，会破坏照片隐私边界。
- 资产变更如果不失效方向和大纲，最终绘本可能使用旧计划。
- 幂等键如果只保护最终生成，不保护上传和视觉参考，会出现重复引用或重复任务。
- session 查询如果没有返回嵌套 asset / visual reference，刷新恢复体验会退回本地拼装。
